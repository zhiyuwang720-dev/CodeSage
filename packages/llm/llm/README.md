# llm —— 模型调用的能力接缝

一个插件化 harness 里,「模型」不该是一块铁板。用模型的消费者要的
是一份稳定的调用契约:发什么形状的请求、拿回什么形状的响应、怎么
指定用哪家模型的哪档配置。提供模型能力的一方则千差万别:不同的
后端协议、不同的版本节奏、随时可能冒出来的新提供者。两头绑死,
消费者跟着提供者改版,提供者背着消费者的包袱 —— 谁也不自由。

能力接缝把两头分开,分界就在本包:

- **契约与消费者住在本包**。请求消息用仓库统一的 ContentBlock
  形状(全系统唯一消息契约,不另立新类型),调用经 llm 服务发起,
  配置经指针解析成一份稳定的调用配置。消费者面向这份契约编程,
  契约不随任何一家提供者的改版而漂移。
- **提供者住在独立包,经注册口子接入**。注册把「提供者名 → 适配器
  工厂」挂到服务上,名字是两者之间唯一的握手。谁先注册、后注册、
  撤销重注册,都在运行期决定,不重新编译任何一方。

## 能力家族:契约与提供者分层

对齐 DSH 的能力家族形态,llm 家族是四个包:

| 包 | 角色 | 对应 DSH |
| --- | --- | --- |
| `llm` | 服务契约 + 消费者 + 客户端(契约层) | dsh-llm |
| `llm_deepseek` | OpenAI 兼容协议适配(DeepSeek / Qwen / GLM / OpenAI) | dsh-llm-deepseek |
| `llm_anthropic` | Anthropic Messages API 适配 | 提供者形态同 dsh-llm-deepseek |
| `llm_replay` | LLM HTTP 录制与回放(传输层,对任何提供者生效) | dsh-llm-replay |

契约层只回答「适配器长什么样」(BaseAdapter 契约、ContentBlock
消息形状、调用配置),不回答「有哪些」。具体适配器住在独立包,
每个包经 install 把自己注册到 llm 服务的能力接缝上 —— 提供者
独立演进,新增提供者只写一个新包,不触碰契约层、服务或任何
消费者。

模型调用的脏活累活 —— 指针解析、重试与退避、辅助请求回退主模型、
成本累计、流式事件组装、截断工具调用防护 —— 随转移住在契约层:
客户端、消息类型、重试、成本、模型配置(profile 与指针的单一
配置源)都是 `llm` 包的组成部分。llm 包不引用任何 codesage 代码
—— 这里是「转移后的新家」,不是「对旧家的引用」。

与 DSH 的一个刻意差异:回放在传输层做(挂在 http 客户端上),
对 deepseek/anthropic 所有已注册提供者通吃 —— 一份录制全家可
回放;DSH 的回放是适配器级,只回放自家协议。

转移是分阶段的:codesage 的旧 ai 目录暂留,等 harness 其余模块
(会话、系统提示、工具、代理)依次迁入各自包后统一清理。

## 调用路径

消费者经 llm 服务发起调用,整条链路只认这份契约:

1. **指定模型**:指针(main / task / compact / quick 之类别名)、
   配置里的 profile 名、或 提供者:模型 字面量 —— 三种写法解析到
   同一个东西:一次调用的完整规格,包括提供者名与模型名。
2. **发起调用**:非流式一次拿回完整响应,流式拿到事件序列。请求
   与响应的消息形状都是 ContentBlock。
3. **计量记账**:响应带回的真实 usage 按 提供者+模型 聚合进计量
   服务;发请求之前想知道量级,用固定密度启发式估算 —— 每 4 个
   字符折 1 token,块与角色各带固定开销。

## 提供者怎么进来

提供者包做三件事:写一个适配器工厂(输入 profile 与共享 http,
输出实现了调用契约的对象)、在包入口提供 install(把一组提供者
名注册到 llm 服务)、持有注册句柄。句柄撤销,注册解除,适配器
随组合卸载一起清理。同名重复注册被拒绝,且一次注册多个名字是
原子的 —— 不存在注册到一半的中间态。

```python
from llm import LLMService
from llm_deepseek import install

ctx.plugin(LLMService)   # 先有契约服务
install(ctx)             # 再挂提供者:deepseek / openai_compatible 等名可用
```

能力接缝是唯一入口:未注册的提供者名在解析时直接报错(提醒加载
对应提供者包),不存在静默回退到某个「默认提供者」——用哪家,
组合显式说了算。

回放模式:llm_replay 包的 make_http 构造带回放能力的 http 客户
端,注入 LLMClient 即可 —— 录制流量、回放命中、miss 报错,CI
靠它抓响应漂移。

## token 计量

计量分两层,各管各的问题:

- **估算**:发请求之前就要知道的量级。固定密度启发式按块类型
  递归计价 —— 文本/思考按字符密度,工具调用按工具名加参数 JSON,
  工具结果递归计价再带载体开销,未知形状按 JSON 序列化兜底。
  它不是计费依据,是量级参考。
- **聚合**:响应带回的真实 usage 按 提供者+模型 分桶累计 —— 一个
  组合可能同时用多家提供者,账分开记,合起来看才是总量。

DSH 原版计量里的 replay 感知投影(逐事件重放会话定价)不在此包
范围内:它依赖会话事件溯源,那是 session 包铺好接缝之后的事。

## 与 DSH 的映射与删减

家族对应 `@deepseek-ai/dsh-llm`(服务 + 调用配置 + 适配器注册)、
`@deepseek-ai/dsh-token-meter`(估算与聚合)、以及 deepseek /
replay 两个提供者包,按项目路线图砍掉了几块:

| DSH 能力 | 处置 | 说明 |
| --- | --- | --- |
| 服务、调用配置、适配器注册 | 保留 | 形状照搬,命名改 snake_case |
| 消息类型 | 复用替代 | 直接复用仓库 ContentBlock 契约 |
| token 估算启发式 | 保留 | 常数与递归规则同源 |
| 提供者独立包(deepseek/replay) | 保留 | 全拆对齐,install 注册 |
| replay 感知计量投影 | 砍掉 | 依赖 session 事件溯源,等 session 包 |
| 图像、模型发现、attribution | 砍掉 | 不在最小 harness 核心路径 |
| 提供者热替换(replace) | 砍掉 | 撤销重注册已覆盖绝大多数场景 |

## 测试

```bash
cd packages && python -m pytest llm/ -q
```

契约层测试用自造的 fake 适配器走通整条接缝:注册 → 调用 → 撤销
→ 重注册,以及重复注册拒绝、全有或无一体的回滚。提供者包测试
从 codesage 迁移(离线 MockTransport,不触网):转换逻辑、流式
事件、HTTP 错误分类、VCR 录制回放,以及 install 端到端注册。
