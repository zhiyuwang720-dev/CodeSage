## scope 包:给「贡献」贴标签,让每个 Agent 只看到自己的

> 本节是架构叙事,不读代码即可理解。想看实现时的入口见 §6。

### 1 它解决什么问题

一个组合里通常跑着多个 agent(主 agent + 若干子 agent)。每个 agent 都会做
四类「贡献」:注册工具、追加提示词段、声明模板变量、挂事件监听器。

没有作用域:所有贡献混在一个大锅里 —— agent A 注册的工具 agent B 也能调,
A 的监听器会被 B 的事件轰炸,A 追加的提示词段会出现在 B 的组装结果里。
scope 解决的就是这件事:**把贡献按属主隔离,同时让祖先能看穿子孙**。

它明确**不是权限机制** —— 只管「看得见/看不见」,不管「能不能用」
(官方注释原话 "security and authority are non-goals")。这对 CodeSage 很重要:
scope 与现有权限链(deny > ask > allow)正交,两条线不会冲突。

### 2 三个核心概念

1. **作用域(Scope)= 一个带标签的 ctx**。组合为某个 agent「铸造」作用域时,
   在那个 ctx 上盖一个**戳**(键值对:`scope key → 该 agent 的身份对象`)。
   ctx 派生子 ctx 时戳自动继承(沿原型链),所以**任何在作用域 ctx 下注册的
   东西,自动携带这个戳** —— 贡献者不需要做任何额外动作。

2. **作用域链(scopeParents)= 父指针,单向向上**。作用域可以有父子关系
   (子 agent 的作用域是父 agent 作用域的子)。链是一个弱引用表
   (作用域 → 父作用域),只记录「谁是谁的祖先」。父子绑定**只允许一次**,
   唯一的重绑通道是原绑定者手里的 rebind 句柄(组合重建会话时才用)。

3. **路由载体(carrier)= 事件上挂的「路由牌」**。作用域里派发事件时,事件
   对象上要挂一张牌(牌上写着「此事件属于谁」)。cordis 的派发机制按牌筛选
   监听器。scope 包提供一个工厂:把任意对象变成「带路由牌的载体」。

### 3 事件如何流动:向上流,不向下流(核心不变量)

```
组合级(无标签)监听器 ←────── 永远放行(全局监听器)
主 agent 作用域   ←───────── 能收到主 agent 自己 + 所有子作用域的事件
子 agent 作用域   ←───────── 只能收到子 agent 自己(及其子孙)的事件
```

规则一句话:**事件从派发处沿父链向上流;监听器按自己的标签对号入座。**

- 无标签 ctx 的监听器(常驻组合级):所有事件都放行 → 组合可以观察全局。
- 带标签的监听器:只有当「事件的牌」在**它的父链上**时才放行 ——
  即祖先作用域的事件,它收不到;它自己及子孙的,它收得到。

类比:**公司广播**。总部广播全员都听得到;分部门的广播只有本部门
(及其下属)听得到。所以主 agent 能监听所有子 agent 的事件(调试、汇总),
子 agent 听不到主 agent 的内部活动(隔离)。

### 4 注册与回收:每作用域一张表,销毁自动清空

- 任何「作用域注册」= **在所属作用域的表里插一行 + 记下撤销方式**。
  撤销由 cordis 的 effect 机制接管:作用域销毁时,它的所有注册按启动逆序
  自动回滚 —— 注册者自己不用写清理代码。
- **表是惰性创建的**(第一个贡献出现时才建),**销毁时空表直接回收**:
  长期运行的组合不会因空作用域泄漏内存。
- **撤销幂等**(重复撤销无害);且撤销的瞬间,迭代中的旧表与新插入**脱离**
  (表清空时换新表实例)—— 保证热更/重入时没有幽灵状态。
- 作用域销毁是「停稳」语义:先 dispose,再等所有异步收尾彻底结束才返回,
  保证「销毁后绝无幽灵回调」。

上层包怎么用这套机制(`ScopedLayers` 模式,被 tools / system-prompt 复用):

- **结构**:全局层(立即构造,常驻)+ 作用域层表(惰性,一作用域一张)。
- **查找 = 全局 + 沿父链各层合并,最近的胜(就近遮蔽)**:
  agent 可以覆写祖先给它的某个工具/提示词段,其他贡献照常继承。
  例:主 agent 给子 agent 注册了一个 `bash` 工具;子 agent 在自己的作用域里
  注册同名 `bash` —— 子 agent 看到的是自己的版本,组合和主 agent 看到的
  仍是原版。
- 注册表上还可以挂「变更通知」:注册/撤销时通知宿主(UI 联动、测试断言)。

### 5 工程细节速览

| 机制 | 作用 |
|---|---|
| 熔断式停稳(quiesce) | 销毁后追等所有异步收尾,防幽灵回调(§3.4) |
| 父链环检测 | 绑定前沿父链检查,遇到自身即抛错(防循环作用域链) |
| generation 迭代纪律 | 表清空换新实例,旧迭代器与后续插入脱离(§3.4) |
| 事件载体不变式(可选) | 派发检查岗:作用域事件必须挂路由牌,且牌上主体与事件 payload 一致 —— 防开发期「忘挂牌/挂错牌」静默 bug。依赖 dsh-invariants,移植期可后做 |
| 最近标签语义 | 一个 ctx 只携带最近的一个作用域戳(嵌套时内层覆盖外层,不累积) |
