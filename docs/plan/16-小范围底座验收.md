# 16 小范围底座验收

CodeSage 小范围底座验收计划：快速审查、双 Worker 与四个执行契约

## 1. 目标与范围

在现有 CodeSage 上完成一次可复现的底座验收：使用**本地 PostgreSQL、Redis 和两个独立 ARQ worker**，验证快速审查完整运行、跨进程取消、进程中断后恢复，以及已完成视角的结果复用。

本次保持现有模型配置、审查提示词、安全／架构／质量三个 Agent 和综合规则不变。新增四个契约，并接入实际执行与恢复路径，不能只添加未被使用的数据类型。

**本次不做：**

- PR-AF 深度流程、自动路由、新 Agent、Skill 进化。
- 通用 DAG、阶段级跨 worker 分发、Temporal。
- 全量 API 重构、替换 QueryLoop 或 SessionStore。
- GitHub 发布、S3、组织权限、前端改版。
- 企业吞吐压测或真实审查质量提升实验。

任务调度粒度仍是**完整 PR 审查**：不同 PR 可以由不同 worker 执行；一个 PR 内三个视角继续使用现有并行机制。恢复时允许另一个 worker 接管完整任务，并跳过已完成视角。

默认验收不调用付费模型：使用测试专用、可控的模型响应替身，保留真实 QueryLoop、工具调用、SessionStore、编排器和数据库路径。真实模型冒烟仅提供可选入口，不自动执行，也不修改已有模型配置。

## 2. 实施顺序与必要改动

### 步骤一：建立现状基线和独立验收环境

先运行并记录以下现有测试的结果：

- `tests/agent/` 下的 worker、queue、task executor、task resume 测试。
- `tests/pr_review/` 下的 stage store、resume checkpoint、resume incomplete 测试。
- 与本次修改相关的 runtime/session 测试。

记录原有失败，不得将已有失败隐藏、删除或整体跳过。

新增独立验收环境：

- PostgreSQL 16、Redis 7，本地容器运行。
- 独立数据库 `codesage_acceptance`、队列 `codesage:acceptance:agent_tasks`。
- 两个独立 worker 进程，每个 `AGENT_WORKER_CONCURRENCY=1`。
- worker 模式固定为 `AGENT_TASK_EXECUTION_MODE=worker`。
- 每次验收使用独立临时产物目录和测试数据。
- 环境变量必须在导入应用 settings、数据库 engine 前设置。
- 不读取或修改现有业务数据库，不覆盖 `backend/.env`。

提供一条验收命令负责启动依赖、等待健康、准备 schema、启动两个 worker、执行测试并生成报告。退出时清理本次启动的进程，失败时保留日志和产物；删除数据必须显式指定，且仅限验收资源。

### 步骤二：增加四个契约

集中放入 `backend/app/services/contracts/review_execution.py`，使用现有 Pydantic 风格，禁止契约层导入 ORM、worker 或 API。

| 契约 | 字段与规则 |
|---|---|
| `ReviewRunIdentity` | `schema_version=1`、`run_id`、`task_id`、`source_kind`、`repository_key`、可空 `pr_number/base_sha/head_sha`、`diff_sha256`、`config_fingerprint`。Git 输入必须有固定 base/head；纯 diff 输入允许 SHA 为空。身份一经持久化不得在 resume 时重新生成。 |
| `ExecutionContext` | `identity`、`attempt_id`、`worker_id`、`lease_epoch`、`workspace_root`、`artifact_root`、`deadline_at`。目录只供可信运行时使用，不自动注入模型。不得包含密钥。 |
| `StageResult` | `schema_version=1`、`run_id`、`stage_type`、`status`、可空 `session_id`、现有 `ReviewFinding` 列表、`artifact_refs`、`stats`、可空 `error_code/error_message`。状态为 `completed/incomplete/failed/cancelled`；`completed` 可有零发现，但必须经过现有完成门禁。 |
| `ArtifactRef` | `schema_version=1`、`artifact_id`、`run_id`、`kind`、`relative_path`、`sha256`、`size_bytes`、`media_type`。路径必须位于对应 run 的产物根内，不允许绝对路径、目录逃逸或符号链接越界。 |

具体接入要求：

- 首次执行生成并持久化 `ReviewRunIdentity`；resume 保持 `run_id`，创建新的执行 attempt。
- `config_fingerprint` 包含影响恢复兼容性的模型参数、提示词、工具配置及快速流程版本，排除凭据。
- resume 校验输入和配置指纹；不一致时拒绝复用旧 Checkpoint，明确提示创建新任务。
- 每个视角结果转换为 `StageResult`，用于写入 Checkpoint和恢复预填。
- `ArtifactRef` 至少用于保存输入 diff 和最终结构化结果，并实际验证哈希。
- 已有 API 请求和响应保持兼容，不要求前端修改。

### 步骤三：最小化接通执行入口

现有 worker 反向调用 API 私有执行函数。此次只抽离**快速 PR 审查直接需要的执行路径及必要辅助逻辑**，形成应用服务入口：

`execute_quick_review(task_id, dependencies)`

API 与 worker 均调用该入口。保留旧入口的薄兼容包装，避免一次性修改其他审计类型和所有历史测试。

`dependencies` 提供测试所需的模型服务、数据库工厂及运行观察器注入点：

- 默认使用现有生产依赖。
- 测试 worker 显式注入测试模型。
- 不提供普通 API 参数让用户任意切换模型替身。
- 不允许通过伪造 dispatcher、直接写入完成状态替代集成验收。

不得借机重写主循环、模型协议或全部 3,069 行 endpoint 文件。

### 步骤四：补齐任务级执行所有权

两个 worker 下验收必须有数据库级执行所有权，不能只依赖内存字典或 ARQ job ID。

新增一张与 `AgentTask` 一对一关联的 `review_execution_runs` 表，保存：

- 身份 JSON。
- 当前 attempt、worker、递增 `lease_epoch`。
- `lease_expires_at`、最后心跳。
- `cancel_requested`。
- 当前投递标识。

采用 PostgreSQL 行锁完成原子领取：

- 有有效 lease 的任务不能被第二个 worker 再次领取。
- worker 每 5 秒续租，lease 为 20 秒，均使用数据库时间判断。
- lease 过期可由其他 worker 领取并递增 epoch。
- 任务终态、阶段完成和 Findings 提交必须在同一事务中校验当前 epoch 与取消状态。
- 失去 lease 的 worker 停止新工作，不能覆盖任务或阶段结果。
- 保留现有进程内取消机制作为加速手段；数据库取消标记为跨进程依据。

本轮只保证任务级单一有效执行所有者；不实现通用分布式锁服务或完整事件溯源系统。

新表使用项目现有 Alembic 机制添加，不能依赖 `create_all()` 自动修改旧表。旧任务首次进入新入口时允许初始化执行记录；缺少身份的历史 Checkpoint 不自动冒充可安全恢复，返回明确的不兼容原因。

### 步骤五：明确取消、恢复与投递行为

- **取消**：先持久化取消标记，再通知本地执行；其他 worker 使用现有数据库 watcher 感知。晚到完成不能把任务改回 completed。
- **恢复**：保留身份和已完成阶段；重新设置任务可执行状态、清除取消标记，并生成新的投递标识。执行时创建新的 attempt。
- **重复投递**：同一执行任务即使被投递两次，也只有一个有效 owner；已完成任务不得重新调用模型。
- **强制终止**：依靠 ARQ 对中断任务的重新执行及数据库 lease 到期接管；不把业务状态仍为 running 当作永久跳过理由。
- **手动 resume**：使用新的投递标识构造 ARQ job ID，避免旧 job 结果保留期阻止重新入队。
- **已完成阶段**：使用保存的 `StageResult` 预填，模型调用次数不增加。
- **未完成阶段**：有可用 session 则走现有会话续跑；不能恢复时明确记录重新执行，禁止伪装为无损续跑。
- **外部调用边界**：本轮不承诺未提交模型调用零重复；报告分别展示已完成阶段复用和中断阶段可能重放。

## 3. 验收测试

新增独立 `worker_acceptance` 测试组，使用真实 PostgreSQL、Redis 和两个进程。测试不 mock 队列、数据库、编排器或阶段存储。

测试模型通过正常模型服务注入点返回确定性的工具调用和最终结果，至少实际执行一次 fixture 内的只读工具。fixture 不需要任意 shell，也不包含外部仓库或真实凭据。

| 场景 | 操作与断言 |
|---|---|
| 完整运行 | 提交快速审查，最终 `intake`、三个 `review:*`、`report` 均完成；Findings、Session、StageResult 和产物哈希一致。 |
| 两个 worker 都在工作 | 提交两个带同步屏障的任务，确认分别记录不同 worker/PID，并出现执行时间重叠；不能仅证明两个进程启动成功。 |
| 跨进程取消 | 通过控制端取消另一 worker 的任务，10 秒内停止新增测试模型请求；任务最终 cancelled，不能被晚返回结果改成 completed。 |
| 取消后恢复 | 等一个视角已持久化完成、其他视角仍运行时取消；停止原 worker，通过 resume 让第二个 worker 接管。身份不变、attempt 改变，已完成视角调用计数不增加。 |
| 强制崩溃恢复 | 在相同持久化屏障处强制终止 owner，保留第二个 worker；90 秒内开始有效接管，最终结果与不中断基线一致，已完成阶段不重跑。 |
| 重复投递 | 用不同队列投递标识模拟同任务重复消息，数据库仅允许一个有效执行 owner；阶段和最终 Findings 不重复。 |
| 旧 owner 晚提交 | 构造过期 epoch 的结果提交，明确拒绝，当前任务和阶段不变。 |
| 假完成保护 | 返回现有 `requires_retry`／incomplete 结果，不得将该视角和任务标记 completed。 |
| 恢复身份不一致 | 修改 diff、配置指纹或源码版本，resume 拒绝复用旧结果，错误原因明确。 |
| 产物完整性 | 破坏产物正文或使用越界路径，加载失败；不能继续使用损坏 Checkpoint 或读取根外文件。 |

用数据库提交屏障和测试模型请求记录控制故障时机，禁止依靠任意长 `sleep` 猜测阶段完成。

正常运行、取消恢复、强制崩溃恢复三类场景分别连续通过三次。测试替身的调用计数只证明恢复行为，不作为真实模型费用或准确率数据。

## 4. 交付物、执行边界与通过标准

**交付物：**

1. 四个契约及序列化、校验、兼容测试。
2. 快速执行入口的窄范围抽离。
3. 任务执行记录迁移、lease 与条件提交。
4. 最小本地产物读写实现。
5. 独立本地验收环境、测试 worker 和一键脚本。
6. 验收说明与结果报告：commit、配置、依赖版本、测试结果、两个 worker 身份、阶段调用计数、恢复时间、失败日志位置及已知限制。

**实施顺序：**

基线测试 → 契约及兼容接入 → 单 worker 完整运行 → 任务 lease → 双 worker／取消 → 恢复与故障测试 → 文档与回归。

**预计工作量：**约 8—12 个有效开发日；若现有恢复测试已失败或真实 Harness 无法通过依赖注入测试，先提交阻塞诊断和最小修复，不能以增加新 Agent 或替换运行时解决。

**给执行者的约束：**

- 保留用户现有未提交修改，不重置工作区。
- 不更换模型、提示词和 Agent，不修改现有 `.env`。
- 不启动付费模型批次、不写 GitHub、不触碰真实业务数据。
- 不把集成测试改成全 mock 来获得通过。
- 不扩大到深度审计、全量安全重构、阶段级调度或前端改版。
- 依赖缺失或 Docker 不可用时明确报告阻塞，不改用 SQLite 或内存队列冒充验收。

**最终通过标准：**四个契约进入实际快速审查路径；现有相关回归无新增失败；两个真实 ARQ worker 能完成运行、取消和恢复；已完成视角得到复用；重复投递与旧 owner 无法造成重复有效提交；结果可以通过一条命令复现。
