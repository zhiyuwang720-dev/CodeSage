# Spec 21B：确定性分包、覆盖账本与恢复

版本1.0，2026-09-14。状态：待21A通过后实施。配套[Plan21](../plan/21-可信审查上下文与PR领域工具.md)、[21A](21A-可信输入与PR领域工具.md)、[验收台账](21-验收矩阵与实施进度.md)。

## 1. B-R01：范围与分发边界

保留security/architecture/quality三视角，不新增动态规划、critic、adversary、compound-finder。模型角色不变，运行单元变为 `packet × perspective`。ARQ仍领取整个PR；单owner在进程内调度短session，不引入阶段级队列或通用DAG。

小PR生成单packet，同样走统一管线，不维护两套完成逻辑。大PR多个packet，task级总预算/并发/取消规则统一；不能把原预算乘以包数。

## 2. B-R02：确定性计划契约

`ReviewPacketPlan`：schema_version=1、run_id、manifest_hash、planner_version、tokenizer_version、policy_hash、packets、excluded_units、plan_hash。

`ReviewPacket`：packet_id、primary_unit_ids、reference_unit_ids、target_file_ids、estimated_tokens、continuation_of?、reason、order。packet_id由plan输入与成员IDs计算，不用随机UUID。相同输入、策略及估算器版本输出完全一致。

规划是代码处理，不调用模型。默认按规范路径目录分组再按文件/hunk顺序first-fit，目标patch预算4096估算token；实际包预算还须满足21A请求窗口约束。单文件跨包允许，单超大hunk按连续diff行分段；超长行按fragment拆分并保留原定位信息。参考重叠不计主覆盖。

守恒：每个需审查change unit恰好属于一个primary packet；reference可重复；excluded有固定reason/policy_version；漏项、多重primary、空计划但非空diff为规划错误，第一次模型调用前拒绝。

最小单位定义沿21A：正常hunk为单位，拆分后segments替代父hunk作为覆盖叶节点；metadata-only独立单位。不能同时把父hunk和segment计入分母。新增/删除/重命名/二进制均在manifest有归属，支持文本范围之外内容明确exclusion。

## 3. B-R03：执行与并发预算

默认每task最多3个在途模型会话/请求，复用现有provider准入限制；调度顺序round-robin视角与稳定packet order，防止前一个视角耗尽全部预算。每个unit session仅收到当前包、全局有界manifest、必要引用及固定能力。

建立run级TokenBudget状态：limit、known_consumed、reserved_inflight、unknown_consumption、version。单次调度原子预留estimated_input+max_output，结束按usage已知量结算；usage未知保留保守reservation并标unknown，不能释放为0。失败重试、finalizer、辅助请求占同一预算。

预算预留/结算通过控制平面持久化服务与当前epoch校验；进程内锁不能代替恢复后的账本。可使用执行记录JSON并加版本的短行锁事务，不新增外部预算服务。恢复时未结算在途预留按unknown保守保留，报告可能重放开销；本轮不承诺实际费用绝不超过预算。

每单元默认max_turns=min(12, task.max_iterations)，同时task级总轮次沿配置硬上限，不能每包复制原上限。无足够输入+输出预算则不发请求，保存剩余单元；不得只给极小输出逼模型伪完成。

## 4. B-R04：持久化与事务

新增 `review_work_units` 表，使用Alembic迁移。字段：id、run_id（关联review_execution_runs现有真实PK映射）、packet_id、perspective、plan_hash、status、session_id?、stage_result_json?、result_artifact_ref?、attempt_id?、lease_epoch、started_at?、completed_at?、error_code?、updated_at。唯一键 `(run_id,packet_id,perspective)`。

run_id在现表身份JSON中若无独立可引用列，使用已有task_id外键并对identity.run_id校验；迁移设计在实施时与真实表定义对齐并记录，禁止凭本文假定已有run_id列。task内唯一单元键不得因attempt变化而变。

单元状态pending/running/completed/incomplete/failed/cancelled。完成载荷复用StageResult，stage_type=`review:{perspective}:packet:{packet_id}`，不把单元结果挤进父阶段单个session字段。父stage保持现有intake/三个review/report，API可聚合并附unit摘要。

持久化仅经 `ReviewResultService` 扩展方法：register_work_plan、start_work_unit、commit_work_unit、aggregate_perspective、commit_success。底层repository不commit；协调器不直接操作ORM。每次写阶段/Findings/终态必须同事务校验epoch、有效lease和cancel_requested。

文件产物先内容寻址原子写，事务中登记可信引用；事务失败产生的孤立文件允许保留并清理，不把文件存在当已提交。完成单元结果、coverage、关联session和费用结算在同一业务事务或明确幂等关联事务内，任何未原子关联部分必须有重试校验，禁止只标状态不存结果。

## 5. B-R05：覆盖与完成

每个perspective×unit维护planned、delivered、reviewed、blocked/excluded。delivered由初始context/成功工具返回登记；reviewed要求该单元已完整提供、模型有效FinalizeReview包含该单元且证据/完成门禁通过。模型声明不能把未交付单元标reviewed。

正常完成要求全部必需单元对三个视角reviewed，且所有work unit completed。父review stage才completed；全部父阶段及结果门禁通过才task completed。报告注明覆盖的是声明流程和文本范围，不保证语义判断完整。

budget_exhausted/context_unavailable/单位未读完使父阶段incomplete、task FAILED且可恢复，保留部分findings。没有完整final artifact时只输出partial诊断包；不能生成成功报告并在脚注说没读完。

默认无新增ignore列表；binary/submodule/LFS等沿21A显式exclusion。排除策略变化纳入plan指纹，不在恢复时悄悄删未完成单位缩小分母。

## 6. B-R06：恢复与重放

恢复先验证identity、snapshot、manifest、plan_hash、context/tool策略版本；一致则重新生成attempt并加载单元。completed单元只读可信StageResult/产物，不创建新session或模型请求；running单元有可用session走既有恢复，否则记录restarted。

新owner能恢复整task。旧owner晚提交单元、预算和父阶段全部拒绝；已完成task重复投递不调用模型。丢失的单元提交允许模型重放，但不得重复有效提交或重复合并findings。

取消持久化标记后取消在途短session，不启动剩余单元。恢复清除取消按既有新delivery流程；已完成单元不重跑。超时/强杀可能丢失遥测和usage，报告unknown而非费用0。

仅环境路径修复不改变identity；修改plan策略、模型、prompt、工具或预算语义版本默认拒绝旧checkpoint并提示新任务。增加预算的专门续审命令本轮不做；相同预算耗尽再次resume应立即返回预算原因，不重复消耗。

## 7. B-R07：结果综合与跨包影响

复用原category指纹去重、严重度规则及上限；每个finding保存source packet/session/perspective和EvidenceRef。规则引擎每个run固定diff执行一次，不随packet重复运行。

不同包的参考片段重复不导致finding重复；同位置不同category不能合并。固定快照SearchSource/ReadSource仍可跨packet读取，读取不会自动把另一个packet标reviewed。聚合阶段不拼全部原始diff或全部推理历史给新模型。

原综合层追问最多两轮/视角的语义保留为全task限制，不每包复制。追问路由到相关源单元session；不得将所有单元payload塞入一个超长追问prompt。无法在预算内核实则suspected/needs_verification并展示来源。

## 8. B-R08：观测与评测

增加packet_id/work_unit_id/plan_hash到Trace/日志/诊断行，不用高基数ID当Metrics标签。报告包括planned/delivered/reviewed/excluded/blocked数量、图谱候选覆盖（若启用）、单元耗时/usage/重试、恢复复用和未知开销。

评测对照分三组：旧轨迹诊断（只作历史观察）、21A环境正确的三视角、21B同环境分包。真实模型/价格/fixture/并发配置必须相同才能比较资源；diff_only与full_source分组，不把权限改变造成的token下降当纯算法优化。

JSONL+静态HTML继续沿Plan20；执行状态仍存业务PostgreSQL，评测展示无需直接查库。图索引可用本地存储，不构建新的评测数据库。

验收B01—B10见统一矩阵。正常、取消恢复、强杀接管各连续三次通过；依赖不足明确blocked，不mock业务事务换绿。
