## 1. 目标、范围和进入门

目标：PR 语义从通用控制面移入 PR 节点，通用 Harness 从 PR 应用执行层分离；保留既有身份、快照、模型出口、阶段/Findings/终态事务和 API 行为。

进入条件：21A A01—A16 有当前代码的验收证据，已知基线失败有明确归属；仅“代码基本完成”不能直接签收。不能在移动过程中补做 21B 分包。已有未提交修改保留，移动与业务修改分别提交。

本阶段不改数据库物理表名，不换模型/提示词，不更换 QueryLoop、SessionStore，不引入远程节点、DID、通用 DAG。22B 才增加节点投递/背压机制。

至少运行并保存当前真实测试命令：`tests/architecture`、`tests/agent`、`tests/pr_review`、`tests/runtime`、`tests/session`、相关 tooling/permission/observability、21A foundation 和 worker_acceptance。允许按测试收集结果选相关子集，但报告必须列出未运行范围与原因。

记录任务状态、ReviewRunIdentity、attempt、阶段 ID、session ID、模型请求数、Findings、输入/结果产物 hash 的基线。迁移后 fixture 相同，语义值须相同；时间戳、随机 task/session ID 可使用显式规范化映射，不得过滤状态或错误字段。

## 4. 22A-R03：可执行依赖规则

1. control_plane 不得导入 nodes、node_runtime、LiteLLM、PR prompts/Findings；对输入 schema 只检查平台信封，PR 输入校验由产品应用服务完成。
2. node_runtime 不得导入 nodes/pr_review 或 FastAPI endpoint。PR 节点可以依赖 node_runtime、平台纯契约及注入端口。
3. PR/domain 不得依赖 SQLAlchemy、ARQ、FastAPI；PR/application 不直接 commit；persistence 不反向调用用例。
4. control_plane/runtime_api 是应用服务，不等于 HTTP endpoint。api 路由可以依赖它及 PR commands，但不能执行模型、Git 或 ORM 结果事务。
5. 跨域 UoW 实现在 bootstrap/基础设施适配器。通过闭包/注入 repository 参与同事务，不能让平台业务 import PR ORM 达成原子性。
6. 禁止通过 `importlib`、字符串类名、公共 `models/__init__` 绕过依赖约束。使用 AST 导入图 + 应用启动/注册测试验证间接依赖。
7. 通用 provider 请求级 retry 保持现有 LiteLLM 行为；本阶段不改变任务级重试归属。全局共享模块只保留已被多域实际使用的技术契约。

兼容表 `compatibility-map.json` 记录旧路径、调用者、新路径、删除里程碑。22A 可保留外部兼容导出；22B 签收前内部消费者必须迁完。历史 Alembic 导入依赖单列，不能修改已执行迁移使旧库无法升级。

## 5. 22A-R04：最小平台契约

Pydantic 风格与当前项目一致；版本 1，额外字段拒绝；JSON 可序列化；不含 ORM、worker、HTTP 类、秘密与绝对本地路径。若已有等价类型，应演进原类型并保留单一权威实现。

### RunCommand

字段：schema_version=1、task_id（现有 task UUID）、agent_type、entrypoint、agent_version、delivery_id（逻辑投递 UUID）、input_ref（不可变输入 manifest 引用）、deadline_at（UTC 或 null）、grant_ref（授权记录 ID）、trace_carrier（可空）。

agent_type/entrypoint/version 由 bootstrap allowlist 匹配，不从消息 import 任意 Python。trace_carrier 仅接受传播字段且总量有界；不接受凭据和任意请求头。input_ref 至少有 artifact_id、sha256、size_bytes、media_type；文件 locator 不属于此信封。

### AttemptContext

字段：schema_version=1、task_id、attempt_id、node_id、lease_epoch（正整数）、delivery_id、lease_expires_at（UTC）、identity_digest。claim 成功后产生。`ReviewRunIdentity.run_id` 与 task_id 继续分别保存；PR ExecutionContext 在节点组合 attempt 与审查 identity、workspace/artifact locator。

### ResultSubmission / SubmissionReceipt

ResultSubmission：schema_version、task_id、attempt_id、epoch、operation（checkpoint/final）、idempotency_key、result_schema、manifest_ref、outcome（completed/incomplete/failed/cancelled）。PR 节点验证 result_schema 对应的业务完成门禁；平台校验身份/epoch/取消/产物引用，不推断 coverage。

SubmissionReceipt：receipt_id、task_id、attempt_id、epoch、operation、accepted_at、manifest_hash。22A 可映射既有事务结果生成，不要求新增远程 receipt 表；22C 才持久化跨网络幂等凭据。不能通过本阶段的内存 receipt 承诺网络重试幂等。

### 三个端口

- RunSubmissionPort：submit、request_cancel、prepare_resume；管理通用状态与投递意图，不准备 Git/PR 输入。
- RunOwnershipPort：claim、renew、assert_current、release；显式 context，不能仅依赖进程 ContextVar 证明授权。
- ResultCommitPort：在同一个 UoW 内验证 owner 并执行注入的业务写入，只有外层 UoW 可 commit。取消终态提交使用单独的受控分支，不能提供任意 `ignore_cancel=True`。

端口是 Python 业务边界，本阶段不生成 REST 客户端。旧 API 请求响应仍由 adapter 转换，不能把内部 AttemptContext 变成可任意提交的用户参数。

## 6. 22A-R05：事务与失败语义

所有受管写入必须在提交所在事务内锁定当前 ownership 行并校验 task/attempt/node/epoch、数据库 lease 时间及 cancel。新增执行路径缺少 ownership 记录时失败，不复用历史 legacy 绕过分支。

PR 结果服务执行：业务校验 → 产物写临时文件/校验/不可变发布 → 打开短 UoW → ownership guard → 阶段/Findings/manifest 登记 → 需要时写终态 → commit。耗时模型/工具/Git 和文件大写入不在持锁事务内执行。

必须保证：

- 阶段写失败时同事务全部回滚；不能出现对应 task completed。之前已提交阶段不回滚。
- cancelled/incomplete/failed 不允许被晚到 completed 覆盖；cancelled 提交只能由当前 owner 的取消分支或控制面经锁确认可终止的转换完成。
- 同位置不同 category 的 Findings 不合并；保留现有去重指纹语义。
- FAILED/cancelled 可见已提交部分 Findings，标 partial；无 final artifact 是合法状态。只有成功终态要求最终投影/产物一致。
- 文件存在不是成功提交；回滚后的孤儿文件不可被恢复预填引用。清理仅针对受管无引用文件，不递归删除用户目录。
- resume 复用阶段前验证输入、配置、StageResult 和 ArtifactRef hash；目录搬移不重新生成身份。
- 暂失 lease 的旧 owner 停止执行，不自行把新 owner 的任务置 FAILED。

SSE 发送与 stage/result 提交用不同注入接口、不同异常处理。SSE 发送失败可降级；业务提交失败必须冒泡为失败/恢复流程。安全事件写入与权威转换需事务关联，OTel exporter 失败不阻塞业务结果。

## 7. 22A-R06：数据模型与裁剪

按架构清单移动 ORM，统一 metadata 登记所有表、relationship 与索引。数据库比较不得产生意外 drop/create/rename；迁移历史保持可升级。不得以 `create_all()` 代替迁移校验。

ToolExecutionReceipt/audit_tool_calls 保留；其用途是恢复，不是普通 trace。现源码未见 AuditModelStreamAttempt/AuditToolCall 类，不再安排重复删除。AgentCheckpoint、AgentTreeNode、AgentTaskReport 仍有 API 调用者，删除前必须完成 UI/API/测试/迁移消费者清单；不允许返回假空对象掩盖移除。

允许清理已证明无消费者的兼容导出与 vulnerability 命名残留；字段/接口删除单独提交并附影响说明。不要趁移动文件改变 category、严重度、证据判定或 model usage 口径。
