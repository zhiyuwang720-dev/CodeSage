# Spec 20：验收矩阵与证据规范

版本2.0，2026-09-10。配套[主规格](20-观测真实性与诊断闭环.md)、[进度台账](20-实施进度与完成情况.md)。前置[Spec20P0](20P0-LiteLLM模型边界与迁移验收.md)的AP01—AP15必须通过。历史W01局部测试保留，但SDK迁移后的用例须重验，不能把规格中的期望值写成实际结果。

## 1. 验收层次与环境

| 层次 | 环境 | 目的 |
|---|---|---|
| L0 | 纯函数、InMemorySpanExporter、InMemoryMetricReader、临时文件 | 字段、算法、状态、脱敏准确性 |
| L1 | 本地HTTP/SSE假provider + 真实LiteLLM SDK/client/薄service/bridge | 验证最终请求、SDK内部重试、usage透传 |
| L2 | 独立PostgreSQL/Redis + 两个真实ARQ Worker + QueryLoop/SessionStore/ToolGateway + Phoenix | 执行和观测端到端闭环 |
| L3 | 显式授权真实DeepSeek模型 + 一个固定公开fixture | 用户可见内容、实际usage、价格与诊断能力 |

L1不能mock SDK/client发送函数；本地服务器以进程外HTTP记录实际请求正文、请求序号、返回事件及时间。SDK可被指向本地endpoint但不能替换成直接返回最终审查结果的模型桩。L2不得mock队列/数据库/dispatcher/结果事务。

本地服务器脚本只返回合法协议响应，工具通过现有网关执行。故障时机用HTTP控制屏障、DB提交状态与进程握手，禁止长sleep猜阶段完成。取消恢复需先确认一个视角StageResult已持久化。

数据库/队列/volume/产物目录全部隔离，沿现有acceptance机制准备schema。不得读取/修改业务库，不更改.env。Docker/镜像不可用标blocked，不用SQLite/内存队列替代L2。Phoenix使用实际锁定镜像记录digest，界面和源码build身份均写入证据。

## 3. 固定数值与退化测试

### 3.1 Token/费用

固定归一数据：request1 input1000/output200/cache400，request2 input500/output100/cache0；测试价miss1/read0.1/output2 USD/百万。request1=0.00104，request2=0.0007，总0.00174。父model.attempt/turn/run不能再加一次。

若request2 usage未知：总成本null、known_cost=0.00104，usage_complete=false；不能得到0.00104的“完整总费用”。第二请求失败但usage已知仍计0.0007。

### 3.2 速率

同进程累计input计数t0=0、t30=600、t60=1200，60秒确认消费速率20 token/s；不能把快照和1800除60。新进程另有起点，拆系列计算。日志/完整请求可用于会话精确计数，Metrics近似窗口必须标方法。

### 3.3 反例必须红

人为恢复以下任何缺陷，对应测试应失败：模型改回review:security、标准token字段删除、usage缺失补0、cached重复加总、capture开关断开、tool参数不写、page limit10即结束、same attempt ID覆盖execution/model、Counter快照直接累加、日志无session、public携带完整prompt。

只做上述变异验证的临时测试不得提交到生产代码。记录哪一条测试捕获了哪一项缺陷。

## 4. 自动验收命令与退出码

实施者提供 `backend/tests/observability_acceptance/run-acceptance.ps1`，并在结果中写实际调用：

```powershell
./backend/tests/observability_acceptance/run-acceptance.ps1 -Suite unit
./backend/tests/observability_acceptance/run-acceptance.ps1 -Suite integration
./backend/tests/observability_acceptance/run-acceptance.ps1 -Suite all
```

all包含model-foundation（AP01—AP15），默认不含付费L3。P0前置支持 `-Suite model-foundation`；unit/integration的局部成功不能替代此前置门。脚本准备独立依赖/迁移/假provider/Phoenix/双Worker，导出证据，退出清理本次启动进程；失败保留日志和产物。删除volume/历史证据需独立显式参数，限制在本次资源范围。

退出0：所选范围全部通过；退出1：测试失败；退出2：环境/证据不完整。报告不得仅看pytest exit0，还需检查测试集合、skip、证据清单、Phoenix可查询与本地文件完整。

L2中正常、取消恢复、强杀恢复各连续3次。恢复timeout profile必须记录；不得以测试短timeout宣称生产90秒接管。健康长任务>60秒原回归必须保留。

## 5. 证据目录与完成判定

每次验收目录：`backend/.acceptance-artifacts/plan20/<UTC时间>-<commit>/`，不提交原始敏感内容。必须包含：

```text
manifest.json               # commit/dirty hash/deps/images/config profile/命令/退出码
capability-matrix.json      # LiteLLM provider/transport、SDK版本、callback粒度与验证ID
tests.json                  # 用例ID/状态/耗时/失败原因/重复次数
baseline.txt                # 既有失败与环境事实
reconciliation.json         # request/span/tool/usage/cost/cohort期望与实际
evidence-index.json         # 文件、sha256、对应REQ/测试ID、脱敏标记
logs/ telemetry/ bundles/ screenshots/
report.md                   # 用户可读结论、限制、待办
```

每项PASS最少关联一条执行命令及原始证据，截图仅补充不替代数值核对。后续代码修改相关路径使证据过期，该行置retest_required。不能用不同commit的局部证据拼成一个不存在的最终版本全通过。

真实L3必须提供：真实endpoint脱敏标识与价格来源、provider/request model、Phoenix请求内容/响应/token/cost界面截图、tool参数/结果截图、完整会话包、金额逐层核对、一个带turn/request/tool引用的实际诊断。没有实际问题时如实解释运行行为，不编造失败案例；另用确定性故障案例证明诊断能力。

若L3未授权/端点不可用/价格未知：记录具体阻塞，自动部分仍可通过，但整体real_verified不可通过。禁止自动发起付费批次消除阻塞。

## 6. 与旧回归的关系

沿用当前四层依赖、lease/fencing、StageResult、ToolExecutionReceipt、消息/Checkpoint、队列和前端接口回归。修复前已确认失败可以标baseline_failure，必须有原日志和相同失败原因；新增失败不允许豁免。必要的测试替换需说明旧断言为何不再有意义及新断言在哪里。

验收完成不是“多少测试passed”，而是需求编号全部有充分证据。最终规则：所有必须需求verified；AP01—AP15通过；A01—A29通过（实际未启用provider分支可在能力矩阵明确unverified，不能影响DeepSeek主路径）；A30通过；无未解决新增回归；诊断包离线可用；台账与最终commit一致。
