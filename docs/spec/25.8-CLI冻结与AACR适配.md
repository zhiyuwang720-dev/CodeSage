# Spec 25.8：CLI 契约冻结与 AACR 适配

版本：1.0。状态：待实施。依赖：25.7 完整终态与事件通过验收。
关联：[Plan25](../plan/25-CodeSageDeep-V1核心移植与原型闭环.md) 第 10 节；[总索引](25-CodeSageDeep-V1核心移植与原型闭环.md)。

## 1. 阶段目标

稳定独立 CLI 的参数、输出、退出码，再让 AACR 用子进程调用同一入口。AACR adapter 只解决启动、等待、结果转换和文件归档，不包含任何审查算法。

本包验收全部可使用 fake 子进程完成。真实模型和真实 benchmark 运行留到 25.9，不能把本包测试隐式变成付费批量评测。

## 2. 必须先核对的现有代码

当前 AACR 的入口是 evaluation/pipeline.py，那里直接 import ocr/claude/codex，并在分支中调 review_instance。reviewers/__init__.py 没有自动插件发现。仅新增 reviewers/codesage_deep.py 不会完成注册。

evaluation/evaluate.py 的 load_target_comments 对非 claude/codex reviewer 使用 OCR 格式：读取 review.comments，每条需要 path、start_line、end_line、content。adapter 必须产出这个现有格式，不能只保存 review.findings。

读取 evaluation/config.py 的 result_path、run_dir，读取 schema.py 的 ReviewInstance，读取 repo_utils.prepare_repo。不能假定存在 projects.json、fixture map 或另一套 codesage_eval 命令。

## 4. CLI 参数契约

必填 --repo、--base、--head。可选 --title、--description、--config、--output、--store-dir、--through。--config 为 UTF-8 JSON，对应 DeepReviewConfig，未知字段拒绝；密钥不放 config。--through 合法值 anatomy/planning/review/cross/final，本包起默认 final。

模型阶段要求显式 --allow-model-calls；anatomy 不需要。这个开关只控制真实调用授权，fake runtime 通过测试入口注入，不向生产 CLI 暴露可执行 Python 路径。

--repo 相对路径按调用者 cwd 解析。--output 和 --store-dir 同样按调用者 cwd 解析，在启动任何模型前转成绝对路径。不能因为子进程 cwd=backend 而把用户相对输出写错地方。

| 情形 | 输出与退出 |
|---|---|
| 无 --output，正常 | stdout 恰好一个 JSON，日志 stderr，退出 0 |
| 有 --output，正常 | JSON 写文件，stdout 为空，日志 stderr，退出 0 |
| completed/partial | 退出 0，调用方必须再读 status |
| 参数/config/ref 错误 | 退出 2，错误 stderr |
| 缺 --allow-model-calls 但请求模型阶段 | 退出 2，零模型调用 |
| 运行失败或输出写失败 | 退出 1，尽可能保留失败结果 |
| 用户 Ctrl-C | 退出 130，取消语义按 25.7 |

--help 必须不初始化数据库和模型。指定 --output 时采用临时文件加原子替换，避免输出半截 JSON；目标由用户显式指定，同名覆盖行为在帮助中说明。

## 5. Adapter 接口与子进程规则

review_instance 的核心输入是 ReviewInstance、repo_dir、results_dir、timeout 和 Python executable/backend 路径。用现有 prepare_repo 获得固定仓库，不再获取 GitHub PR diff。准备仓库可能联网，应在日志与使用说明中明确。

运行命令采用参数数组，不使用 shell=True。cwd 设为 backend 的绝对路径，--repo 和所有输出目录传绝对路径。Python executable 默认 sys.executable，允许调用者显式配置，以支持不同虚拟环境。

adapter 显式添加 --through final，不能受开发期默认值变化影响。只在调用者授权真实模型后传 --allow-model-calls。preview 只显示经过脱敏的计划信息，不启动模型。

每个 case 的临时输出位于该 run 的专用子目录。stdout/stderr 捕获后保存脱敏内容；timeout 终止并等待进程，不能遗留仍在调用模型的子进程。进程树清理采用平台支持的 subprocess 生命周期管理，不复制 OCR 的 clean_worktree：它可能删除用户无关工作区内容。

## 6. DeepReviewResult 到 AACR 的精确映射

必须先检查子进程返回码，再解析完整 JSON，并用业务 Schema 校验。PreparationReport 不能被接纳为 benchmark review。

| DeepReview 字段 | AACR envelope |
|---|---|
| instance.instance_id/repo/base_commit/head_commit | 顶层同名身份字段 |
| 固定字符串 codesage_deep | 顶层 reviewer |
| adapter 开始时间与实际墙钟 | started_at、duration_seconds |
| 子进程退出码 | codesage_deep_exit_code |
| finding.file_path | review.comments[].path |
| finding.line_start/line_end | review.comments[].start_line/end_line |
| severity/title/body/evidence/suggestion | 确定性组合成 review.comments[].content |
| 原始完整结果 | 独立 raw-result.json，envelope 保存引用或 deep_review 字段 |
| metrics | 可保留原始 metrics，不改 evaluator 计算逻辑 |
| stderr | 脱敏 stderr |

content 使用固定格式：“[severity] title”，空行后 body；有 evidence/suggestion 时追加对应段落。不调用模型润色。文件级 Finding 保留 None 行号，不虚构第 1 行。

退出 0 + partial 可保存评测输入，但 summary 必须记录 partial；不能把它和完整成功混为一类。退出非零、JSON 非法或结果类型错误时记录 failed。失败样本不产出可被误认为成功空评论的标准评测文件；保留单独诊断文件与 summary。合法零 Finding 才是 comments=[] 的成功文件。

测试必须直接调用现有 load_target_comments 验证一条映射后 Finding 被读成一条评论，不能只检查 adapter 自己的 JSON。

## 7. 实施步骤与技术红线

1. 冻结 CLI 并补参数/输出测试。
2. 实现纯函数 result→comments，先对接现有读取器测试。
3. 实现子进程包装和异常归档，使用 fake subprocess fixture。
4. 在 pipeline.py 做最小 codesage_deep 注册，验证选择该 reviewer 不落入 claude 分支。
5. 补使用文档，明确 backend 工作目录、真实调用开关、隔离输出、review 与 eval 分开执行。
6. 再运行现有 reviewer 的选择/参数回归，确认原行为未改变。

不改 judge 的提示词、阈值、模型或评分算法。不自动使用 --stage all，不增加默认批量 case 数。不传密钥到命令行或写入镜像，不清理整个 benchmark repo。
