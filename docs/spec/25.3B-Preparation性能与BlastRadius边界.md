# Spec 25.3B：Preparation 性能与 Blast Radius 边界

版本：1.0。状态：已批准。依赖：25.3A 已完成。本包是 25.4 前的性能与稳定性修正，不改变 Preparation Pipeline 的阶段契约。

上位设计：[Plan25](../plan/25-CodeSageDeep-V1核心移植与原型闭环.md)。本包只处理固定 head 上的 Python import 线索和 Anatomy 稳定分组。

## 1. 目标

`compute_blast_radius()` 继续只返回一跳反向 Python import 依赖，但批量读取固定 head 的 Python blob，消除逐文件 `git show` 的进程启动瓶颈。Blast Radius 是 best-effort 线索：超限、超时或 Git 读取失败时允许降级为空结果，并留下简短诊断；不能把空结果表述为“已证明无影响”。

Anatomy 的目录聚类继续保持确定性。本包只稳定 cluster 标识，并给目录分组和超大簇增加可配置边界，不引入 LLM 聚类或跨语言 symbol database。

## 2. 冻结契约

| 项目 | 冻结规则 |
|---|---|
| 影响范围 | 只做一跳：其他文件 import 了 review path 时返回该文件；不遍历传递依赖 |
| 批量读取 | `git ls-tree -r -z` 建立 path/blob SHA，随后一次 `git cat-file --batch` 读取 |
| 模块匹配 | 除 repo 全路径模块名外，支持唯一路径后缀别名，覆盖 `PYTHONPATH=backend` 时 `app.foo` 导入 `backend/app/foo.py` |
| 文件上限 | `max_import_graph_files` 超限抛 `BlastRadiusError`，编排降级为空 related paths |
| 字节上限 | 所有选中 blob 总量超过 `max_import_scan_bytes` 抛 `BlastRadiusError`；单个超大 blob 跳过并记录诊断 |
| 超时 | 批量 Git 读取超时转换为 `BlastRadiusError`，编排降级 |
| 诊断 | 可向 `compute_blast_radius(..., diagnostics=[])` 传入诊断列表；只记录类型、数量或路径计数，不记录源码 |
| cluster ID | 由稳定目录 key 派生 SHA-256 短哈希，不使用结果数组下标 |
| 聚类上限 | `cluster_directory_depth` 控制初始目录 key；超过 `max_cluster_files` 时按剩余路径稳定递归拆分 |

`DeepReviewConfig` 新增：

```python
max_import_graph_files: int = 2000
max_import_scan_bytes: int = 32_000_000
cluster_directory_depth: int = 1
max_cluster_files: int = 24
```

所有字段必须 `ge=1`，并保持 `extra="forbid"`。

## 4. 失败矩阵

| 场景 | 行为 |
|---|---|
| head tree 读取失败 | `BlastRadiusError` → related paths 为空 + `blast_radius_degraded` |
| Python 文件数超上限 | `BlastRadiusError` → 空结果，不静默扫描无界集合 |
| 总 blob 字节超上限 | `BlastRadiusError` → 空结果 |
| 单个 blob 超过 `max_file_bytes` | 跳过该文件，继续；诊断记录跳过数量 |
| `cat-file --batch` 超时 | 转 `BlastRadiusError` → 空结果 |
| Python 解析失败 | 跳过该文件，不失败 |
| 空 changed paths | 不执行 Git 批量读，直接返回空 |
| 非 Python / 隐式依赖 | 本包不保证；空结果只是无 import 线索 |

## 5. 测试与验收

1. 保留现有 path-level import graph 和 relative import 测试。
2. 新增 `backend/app/foo.py` 被 `backend/app/caller.py` 以 `from app.foo import value` 导入时，`compute_blast_radius()` 能返回 caller。
3. 新增文件数超限抛 `BlastRadiusError`。
4. 新增单文件超限跳过且诊断递增；正常依赖不受影响。
5. 新增字节总量超限抛 `BlastRadiusError`。
6. 相同文件输入顺序不同，cluster ID 不漂移；插入新目录不会改变已有 cluster ID。
7. 初始 depth 能合并兄弟目录；超过 `max_cluster_files` 后按子路径拆分且不丢文件。
8. 已知 Blast Radius 失败继续到达 anatomy，诊断包含 `blast_radius_degraded`。

验收命令：

```bash
pytest -q backend/tests/deep_review
```
