## 1. 验收层与命令

L0：纯契约/解析/预算/投影，临时文件。L1：真实Git fixture、真实ToolGateway与QueryLoop、LiteLLM+本地HTTP/SSE假模型，不能直接mock dispatcher产最终findings。L2：独立PostgreSQL/Redis、两个真实ARQ worker、真实SessionStore/结果事务。MCP测试使用固定版本真实本地服务及额外协议故障fixture。

实施者新增 `backend/tests/review_context_acceptance/run-acceptance.ps1`，提供以下待实现命令：

```powershell
./backend/tests/review_context_acceptance/run-acceptance.ps1 -Suite foundation
./backend/tests/review_context_acceptance/run-acceptance.ps1 -Suite packets
./backend/tests/review_context_acceptance/run-acceptance.ps1 -Suite graph
./backend/tests/review_context_acceptance/run-acceptance.ps1 -Suite all
```

foundation=A01—A16；packets=B01—B11；graph=M01—M08且须方案已批准。all默认foundation+packets，不默默启动graph/真实模型。退出0=所选全部通过；1=测试失败；2=环境、用例或证据不全。报告记录选择范围、skip和未验收项，不能只看pytest退出0。21A阶段可独立运行foundation，不以尚未进入21B的packets未实现否定21A，但不得宣称all通过。

数据库/队列/volume全隔离，不改.env/业务库。沿现有acceptance迁移及进程清理方式；失败保留证据，删除资源须显式参数且路径限定。Docker不可用标blocked；不能用SQLite或内存队列冒充L2。
