# 17 底座问题修复实施规格

本规格落实已批准的 `docs/plan/17-底座问题修复.md`，仅修复快速审查执行一致性与真实 Harness。

## 强制不变量

1. 对存在 `review_execution_runs` 的任务，任务、阶段、Findings 写入必须携带当前 `ExecutionContext`，并在同一事务内校验 epoch 与取消标记。
2. Findings 归一化不自行提交；最终 Findings、report StageResult、任务终态在一次 owner 守卫事务内提交。
3. lease 丢失、取消或心跳数据库异常只停止旧 attempt，旧执行不得写 cancelled/failed。
4. runner 返回后以数据库业务状态决定结果，不把“正常返回”当成 completed。
5. resume 校验稳定身份、StageResult 与输入 ArtifactRef，并实际重算产物哈希。
6. run 目录自身及其父链不得通过符号链接逃出 artifact root；最终产物名包含 attempt/epoch，旧 attempt 不覆盖新产物。
7. 验收替身只注入模型服务，不替换编排器；真实路径必须经过三视角、QueryLoop、工具调度与 SessionStore。

## 验证顺序

失败回归 → fencing/事务 → 心跳监督 → 契约恢复校验 → 真实 Harness → 取消、恢复、崩溃及重复投递矩阵 → 三次复跑与报告。
