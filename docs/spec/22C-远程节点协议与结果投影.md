# Spec22C：远程节点协议、恢复存储与结果投影

版本1.0，2026-09-15。状态：not_started，**排在21B验收之后，已列入开发顺序，不再是条件触发候选阶段**。

依赖：[22B](22B-独立节点与可靠投递验收.md)和[21B](21B-确定性分包与覆盖恢复.md)均verified；配套[台账](22-验收矩阵与实施进度.md)。本阶段在本机多容器模拟独立主机，不要求购买服务器、S3或云服务。

## 1. 目标和不可突破的边界

远程PR节点仅通过受控协议领取任务、续租、读取输入、保存恢复状态和提交结果；没有平台数据库/Redis凭据，没有平台文件系统挂载。控制面不导入PR算法，PR节点仍执行完整任务内的packet×perspective。

平台保存通用执行事实、投递意图、授权、内容引用、checkpoint接受记录和最终receipt/outbox。PR产品投影器解释Findings/coverage；节点运行时通过远程存储适配器保存session/work unit/budget。可继续同一个PostgreSQL实例的分schema/角色部署，但DB角色、容器网络与目录权限必须隔离。

本阶段不做跨地域调度、公共节点市场、DID/VC、通用DAG、任意Agent代码上传。不更换LiteLLM、不新增付费模型批次。

## 2. 22C-R01：服务与传输方式

内部API路由前缀 `/internal/v1`，下列路径为目标接口；已有等价路由可复用并在证据中映射，不能留两个写入权威入口。

远程节点采用HTTP拉取任务，不向节点开放数据库和Redis。`POST /node/next` 最长保持20秒等待；服务器在返回前原子claim，返回RunCommand、AttemptContext和受限输入引用。响应丢失用request_id查询/重试返回同一有效claim，不能每次新建attempt。

22B的delivery/reconciler仍是唯一任务级重新派发状态机；HTTP拉取读取同一持久化待派发意图。ARQ保留为本地节点传输adapter及后台投递/投影任务工具，不作为远程HTTP模式的第二执行入口。每个delivery固定transport=local_arq或remote_http；同一delivery不同时供两个adapter领取。22C验收运行使用remote_http。

平台模块只维护任务能力和调度资格。产品API输入准备/PR结果投影仍属于nodes/pr_review/application，可在独立产品适配器进程装配；不要重新塞回control_plane。

## 3. 22C-R02：认证、授权与网络

管理员配置节点allowlist，每节点独立高熵Bearer凭据；服务端存摘要，节点凭据只通过运行环境/文件secret装配，不写manifest/trace。凭据关联node_id、允许agent_type/entrypoint/version、能力上限、有效期和撤销状态。HTTP认证失败401，身份有效但越scope403。

每个API调用重新校验节点身份与task/attempt绑定，不相信body中的node_id。artifact/session/checkpoint只能访问已授权任务；跨任务ID猜测、旧attempt提交、越界引用均拒绝。撤销节点后续租/新增读取/提交被拒绝，现lease自然过期后其他节点接管；已发出的模型调用可能完成，但不能有效提交。

内部协议部署必须TLS；本地隔离验收使用生成的测试CA并验证证书，不能通过verify=false伪装安全链路。外部网关认证和工具能力授权分别验证。节点容器只暴露所需网络：控制面API、测试模型fixture、明确配置的模型/MCP目的地；平台数据库/Redis连接测试必须失败。

允许后续替换mTLS/短期证书，当前不为此建设完整PKI产品。审计记录认证拒绝、claim、续租拒绝、取消、receipt、投影和节点撤销；禁止称为密码学不可否认性。

## 4. 22C-R03：接口与幂等错误契约

所有修改请求有schema_version=1、request_id、task_id、attempt_id、epoch（领取请求除外）。幂等键scope至少含节点/任务/operation；同键同规范请求摘要返回已接受结果，同键异内容409 idempotency_conflict。保存期至少覆盖任务保留期/所有允许重试窗口，不依赖进程内缓存。

| 操作 | 输入/输出重点 | 原子规则 |
|---|---|---|
| POST /node/next | 能力版本、request_id；RunCommand+AttemptContext或204 | 容量、delivery、未取消、lease同事务claim |
| POST /attempts/{id}/heartbeat | epoch；DB lease_expires_at、cancel状态 | 只续当前实例owner；过期/被替换不续租 |
| GET /runs/{task}/input | manifest引用/内容地址 | 授权后读取；不返回平台本地路径 |
| PUT /runs/{task}/artifacts/{artifact_id} | 声明hash/大小/类型+流式内容 | 上传后校验，不自动成为有效checkpoint |
| GET /runs/{task}/artifacts/{artifact_id} | 内容流+hash/大小 | 仅可读取已授权、已发布引用 |
| POST /runs/{task}/checkpoints | revision、expected_revision、manifest_ref | guard+CAS+幂等receipt原子提交 |
| GET /runs/{task}/checkpoints/latest | 最新已接受revision、manifest_ref | 不返回未提交上传文件 |
| POST /runs/{task}/finish | outcome、manifest_ref、幂等键、epoch | guard+final receipt+terminal+outbox同事务 |
| GET /runs/{task}/receipts/{key} | 已接受摘要/版本 | 网络超时后查询事实，不重跑模型 |

错误信封：code、message、retryable、request_id、current_revision?、retry_after?；不得包含secret/主机绝对路径。400 schema_invalid；401/403认证授权；409 stale_owner/cancel_requested/version_conflict/idempotency_conflict；413 payload_too_large；422 artifact_corrupted/manifest_invalid；429 overloaded；503 temporary_unavailable。

节点只对网络中断、429/可恢复503重试相同幂等请求（有界退避，受lease/deadline约束）；409 stale_owner立即停止新模型工作。旧owner查询其已经接受的receipt可返回历史事实，但不能获得新写入权限。

心跳响应缺失时节点不能无限乐观继续：以最后成功续租的往返耗时及本地单调时钟估计剩余安全窗口，扣除至少一个心跳周期的余量，窗口不足暂停新增模型/工具并尝试关闭在途工作。真正写入授权始终由平台数据库时间决定，不能信任节点系统墙钟或客户端自报lease。恢复网络后先查询owner，不自动复活过期attempt。

## 5. 22C-R04：输入、源码和产物传输

复用ArtifactRef完整性语义，但跨边界仅传逻辑ID、hash、大小、类型；relative_path仅在存储服务内解析，不由调用者指定平台任意路径。默认控制JSON上限256KiB；单内容对象上限64MiB，大输入/快照分块，每块独立hash，root manifest记录顺序与整体hash。达限明确拒绝/分块，不截断成成功。

大内容流式上传下载，计算hash，临时文件写入后原子发布；哈希错误删除本次临时对象，不损坏已有内容。并发同hash幂等，跨run读取仍需授权，不能因内容寻址绕过scope。

repository_required任务发布固定base/head的受控源码快照manifest（路径、side、blob hash、模式、大小），节点按需获取blob或预取有界对象集合，在自己的artifact/workspace根物化。禁止依赖API主机repository_path。删除文件从base读取；未修改文件仍可按授权快照读取。

快照不跟随symlink/gitlink，不运行checkout hook/filter/仓库脚本。源对象缺失或版本不匹配模型调用前失败；网络错误不静默降为diff_only。纯diff任务无需下载源码。缓存绑定repository/snapshot/blob版本，不信任工作树内容。

22B共盘locator作为local adapter保留；remote adapter必须经过HTTP实际传输。验收节点不共享宿主目录，删除原owner本地缓存后仍能恢复。

## 6. 22C-R05：会话、单元和预算的恢复持久化

**只上传最终报告不足以实现远程恢复。** 为SessionStore/PR工作单元账本实现远程存储adapter，保留QueryLoop和现有会话协议。节点本地缓存非权威；平台接受的checkpoint manifest是恢复入口。

RecoveryManifest包含：schema_version、task_id、review_run_id、identity_digest、snapshot/plan_hash、producer版本、revision、parent_revision、session消息/turn/checkpoint引用、work-unit StageResult引用、coverage引用、budget ledger引用、输入/结果内容hash集合。PR/Runtime负责schema与业务一致性；平台只校验通用关联、引用存在和CAS，不读取packet语义调度。

checkpoint提交顺序：发布所有不可变内容 → 提交manifest(expected_revision) → 平台guard+revision CAS+receipt → 节点才把该revision视为已持久化。相同版本不同正文拒绝；网络响应丢失查询receipt。并行perspective通过节点内单写协调器合并checkpoint，不用最后写覆盖其他视角。版本冲突先重新读取合并，再按同一逻辑提交，不能丢预算/覆盖记录。

需要展示部分结果时，同一checkpoint接受事务写入通用checkpoint.accepted outbox事件；PR投影器根据已接受revision提取partial Findings。不能依赖节点再发一个可能丢失的展示回调。平台事件只含引用，不解释PR字段；最终receipt与checkpoint事件按任务接受序号投影，避免旧partial覆盖最终结果。

远程预算保留21B保守规则：**发模型请求前预留必须已包含在服务端接受的checkpoint中**；完成usage结算关联provider request ID和receipt，重复回调不重复加账。未知结果保留unknown reservation。复用已完成单元的条件是单元StageResult和会话/预算状态已原子纳入接受manifest。

性能折中允许内容按增量引用上传，manifest不重复全文。不能为了减少HTTP等待异步丢弃关键预留/阶段提交。测量checkpoint上传/接受耗时与字节数，明确其端到端开销。

旧owner离线未提交消息/模型调用允许重放；报告区分已接受revision复用与未接受尾部丢失。不得把未提交的本地session恢复宣称为远程无损续跑。

## 7. 22C-R06：最终结果与产品投影

平台新增或复用通用run/attempt、delivery、checkpoint receipt、result receipt、outbox、projection状态记录。最终结果manifest不可变，由PR节点完成21B证据/覆盖门禁后提交。平台原子验证当前epoch/cancel/引用并写final receipt、execution终态和outbox，不在此事务调用PR投影代码。

outbox由受信PR产品投影器消费，只接受平台已接受receipt。投影器再次验证PR schema、manifest/plan/coverage，幂等写Findings/报告；唯一键至少包含accepted receipt与业务finding指纹，禁止重复事件重复insert。原始节点声明completed不等于产品结果已验证。

两个状态分别公开：execution_status（平台执行已结束）与result_status（pending/ready/failed）。为兼容现有前端，PR任务旧status只有投影ready后才显示completed；pending保持处理中投影，不能让resume误以为模型还在运行。execution已成功、投影失败仅重试投影，不重跑模型。

投影器写自己的业务库/表和applied receipt在同一事务。跨库时ACK平台不是同事务：ACK失败重复消费先查已应用receipt，再重发ACK；平台幂等记录result ready。任何故障均不产生永久丢事件或重复Findings。输入/结果hash相同但receipt不同也不能绕过task范围。

FAILED/cancelled保留已接受checkpoint中的partial Findings；取消发生在finish前则拒绝成功提交，finish已被接受后取消按终态规则返回冲突/已有结果，不撤回历史事实。晚到旧revision的partial投影不得覆盖最终ready版本，按accepted序号单调应用。

## 8. 22C-R07：ORM迁移与回滚

22A/22B保留的混合模型在此阶段实施逻辑分离：通用AgentRun/Attempt/Delivery由平台所有；PRReviewJob保存ReviewRunIdentity、输入配置、plan/coverage/结果关联；session/work-unit内容由远程恢复存储adapter访问，不给节点SQL账号。可继续同PG实例，不要求拆服务器。

先以Alembic增加新表/字段，回填旧task_id与review_run_id显式映射；再切单一写入者。禁止长期双写；过渡只允许事务桥或可核对的单向投影。新老行数、身份hash、stage/work-unit归属、外键和指纹逐项核对。历史无安全身份的checkpoint仍不自动变兼容。

升级时暂停新领取，等待或取消排空旧owner，再迁移、切transport。活跃attempt不能跨存储协议热切换。读兼容视图/adapter保留既有API；旧表不在同一提交drop，删除需后续独立验收。

回滚边界：切换前可恢复旧入口；已有remote receipt写入后回滚必须先导出/映射新接受状态，不能简单代码git回退丢执行事实。报告明确支持的schema版本与回滚限制。

## 9. 22C-R08：本地隔离验收与观测

runner创建两个PR节点容器/进程隔离根、控制面TLS、私有PG/Redis网络、测试模型服务。节点无平台DB/Redis环境变量且网络直连失败；节点之间也不共享session/artifact卷。不以权限字段断言代替连接测试。

覆盖台账22C-T01—T14，完整、取消恢复、强杀恢复各三次，继承21B多包fixture。在一个packet×perspective持久化后杀owner、清除其本地缓存，由另一节点恢复；已完成单元不调用模型，未提交部分可重放并标unknown。

故障点：上传后checkpoint前、checkpoint commit后响应前、finish commit后响应前、outbox发送前/后、PR投影commit后ACK前、节点撤销、控制面重启、网络隔离超过lease。fault必须有可复核持久化屏障，不能依靠长sleep猜测。

OTel用HTTP传播与稳定task/run/attempt关联；成本仍按provider物理请求聚合。报告分列queue/网络传输/checkpoint/模型/工具/投影时延，公布远程化新增开销，不承诺一定更快。模型内容采集/脱敏沿Plan20，评测最终JSONL/HTML离线可浏览。

完成标准：远程节点通过受控协议完整运行/恢复，不接触平台数据库或本地根；结果投影可重试且无重复有效提交；21B覆盖/预算语义保留；提供一条本地隔离复现命令和完整证据。多容器验收不冒充真实跨机网络性能或企业吞吐测试。
