## 2. 测试层和统一入口

L0：契约、AST依赖、纯业务校验；L1：真实Harness/工具/Session接口+确定性HTTP模型服务；L2：真实PG16/Redis7/API和两个ARQ节点；L3：TLS控制API+两个隔离节点、独立根与受限网络。

执行者新增 `backend/tests/plane_boundary_acceptance/run-acceptance.ps1`，目标命令如下，**目前为待实现入口**：

```powershell
./backend/tests/plane_boundary_acceptance/run-acceptance.ps1 -Suite boundaries
./backend/tests/plane_boundary_acceptance/run-acceptance.ps1 -Suite nodes -Repeat 3
./backend/tests/review_context_acceptance/run-acceptance.ps1 -Suite packets
./backend/tests/plane_boundary_acceptance/run-acceptance.ps1 -Suite remote -Repeat 3
./backend/tests/plane_boundary_acceptance/run-acceptance.ps1 -Suite all -Repeat 3
```

boundaries=22A，nodes=22B，remote=22C。all=22A+22B+21A foundation+21B packets+22C；只在对应入口均实现后可返回完整成功，不能静默跳过未实现suite。21M不自动加入all。Repeat只重复各阶段完整/取消恢复/强杀恢复三类高成本场景，其余至少一次；报告列每个iteration独立结果。

退出0=选择范围全部通过且证据完整；1=断言失败；2=依赖缺失、测试未实现、关键skip或证据不足。pytest返回0不能覆盖runner整体不完整。Docker缺失不替换SQLite/内存队列；付费模型默认禁用。

使用独立验收DB/队列/volume，环境变量在导入settings/engine前设置。启动健康等待有超时；退出清理本次进程，失败保留证据。资源删除使用显式Clean参数，只能删除带本次run标签的资源和已解析位于验收根的路径。不读取或修改业务.env。

## 7. 证据格式

证据根：`backend/.acceptance-artifacts/plan22/<UTC>-<commit>-<suite>/`。每次保存：

- manifest.json：spec版本/hash、HEAD/dirty hash、依赖/镜像版本、有效配置（排除secret）、suite、隔离资源、命令/退出码、开始结束时间。
- tests.jsonl：test_id、requirement_ids、iteration、status、duration_ms、原始测试标识、证据路径/hash、失败原因；skip必须注明是否阻断签收。
- ownership-inventory.json、compatibility-map.json、migration-reconciliation.json：所有权/兼容/升级核对。
- deliveries.jsonl、attempts.jsonl、model-requests.jsonl：logical delivery/dispatch、claim/epoch/instance、物理provider请求和复用/重放关联。
- reconciliation.json：输入/plan/阶段/unit/session/coverage/budget/Findings/manifest/receipt/projection核对；不适用字段明确not_applicable。
- logs、OTLP导出、故障屏障记录、原始pytest结果；report.html静态汇总，不依赖连接数据库或Phoenix查看。

secret不得进入报告；模型测试替身的调用计数不能作为真实费用或准确率。所有恢复时间以持久化时间和request记录证明，不使用截图主观估算。
