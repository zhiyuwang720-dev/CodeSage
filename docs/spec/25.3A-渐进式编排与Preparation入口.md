# Spec 25.3A：渐进式编排与 Preparation 入口

版本：1.0。状态：待实施。本包是 25.3 与 25.4 之间的必要交付。
上位设计：[Plan25](../plan/25-CodeSageDeep-V1核心移植与原型闭环.md)。公共规则见 [Spec25 总索引](25-CodeSageDeep-V1核心移植与原型闭环.md)。

## 1. 阶段目标和完成后的使用方式

本包把已经存在的 Git 输入、过滤、结构统计、影响范围模块串成一条实际可以运行的准备链路。开发者输入仓库路径和 base/head，就能看到阶段日志、结构摘要和事件文件。运行过程不调用模型，也不要求模型密钥或 SQL 数据库可用。

后面的每个包都在这条 run 上增加阶段。不要创建第二条 CLI 专用编排，也不要复制确定性分析模块。当前完成准备工作不代表完成代码审查，因此结果明确标记 pipeline_complete=false。

## 2. 开发前检查和已存在接口

先读 services/input_builder.py、directory_filter.py、diff_engine.py、blast_radius.py、evidence.py，以及 schemas/input.py、pipeline.py、config.py、output.py。这些路径均相对于 backend/app/domains/deep_review。

实际已有接口如下；调用时遵守同步与异步区别：

| 接口 | 调用方式 | 返回数据 |
|---|---|---|
| build_review_snapshot(review_input, config) | 同步；含 Git subprocess | ReviewSnapshot |
| compute_blast_radius(changed_paths, repo_path, head_commit, config) | await | list[str] |
| build_anatomy(changes, related_paths=None) | 同步纯计算 | Anatomy |
| build_evidence_packages(findings, snapshot, blast_radius, config) | await；本包不调用 | dict[int, EvidencePackage] |

ReviewSnapshot 已包含 filter_result、diff_by_path、merge_base、base_commit、head_commit、commit_messages。build_review_snapshot 已执行 DirectoryFilter，编排不能再执行一次过滤。Anatomy.files 可能包含 diff，禁止直接把 Anatomy.model_dump() 写入日志。

Blast Radius 当前主要实现 Python import 分析。其他语言可以正常进入准备报告，但不能把空 related_paths 解释成“已证明没有依赖”。

## 4. 输入、输出与内存状态

DeepReviewService.run(review_input, *, through=None) 是唯一执行入口。当前 None 等价于 anatomy；显式请求 planning/review/cross/final 必须在任何模型或 Git 工作之前拒绝，退出码 2。

PreparationReport 位于 schemas/output.py，使用 extra="forbid"。字段要求如下：

| 字段 | 类型与规则 |
|---|---|
| run_id | 本次新生成的运行标识；与存储目录一致 |
| mode | 固定 preparation |
| pipeline_complete | 固定 false |
| completed_stage | 本包固定 anatomy |
| base_commit/head_commit/merge_base | 已解析的完整 commit；base 与实际 diff 起点不能混淆 |
| review_paths/context_paths | 排序后的仓库相对路径 |
| excluded_count | 过滤决定中 exclude 的数量 |
| stats/clusters | DiffStats 和 ChangeCluster，来自脱敏后的允许变更集 |
| related_paths | 去重排序后的允许上下文路径 |
| diagnostics | 简单字符串列表，记录增强分析缺失等问题 |

RunContext 是 orchestrator 内部 dataclass，只持有当前需要的 snapshot、anatomy、blast_radius、diagnostics。不要预先写一套可恢复状态机。业务模型跨阶段在内存传递，JSONL 不作为下一阶段输入。

## 5. 实施顺序

1. 先实现内存 fake store 和 JSONL store，保证 append 接口可替换。
2. 实现 service.run，生成新 run_id，写 run_started。参数验证失败可以发生在 run 创建前。
3. 调用 build_review_snapshot。同步 Git 工作可放入 asyncio.to_thread，保持事件循环可响应；底层原有 subprocess timeout 仍保留。
4. 读取 snapshot.filter_result。写 input_loaded 和 filter_completed，包含计数和 commit。不要伪造过滤开始时间：当前过滤发生在 input 阶段内部，日志注明 filter 已由 intake 完成。
5. 从 snapshot.changes 选择允许的 review/context 变更，排序后交给 build_anatomy。不得把 exclude 中的 secret diff 放入后续模型上下文。
6. await compute_blast_radius(snapshot.review_paths, snapshot.input.repo_path, snapshot.head_commit, config)。已知 BlastRadiusError 可以记录诊断并用空列表继续；未知异常不笼统吞掉。
7. 调用 build_anatomy，再显式构造 PreparationReport。只复制 report 需要的字段。
8. 写 preparation_completed 事件。CLI 将报告写入 --output，或者在未指定 --output 时写 stdout。
9. 补齐 CLI 子进程测试后，用文末真实仓库命令做手工 smoke。

每个真实执行阶段发送 stage_started、stage_completed 或 stage_failed。started 不要求 duration_ms；completed/failed 使用 monotonic 时钟计算耗时。异常日志保留错误类型和简短信息，不输出包含完整 diff 的对象 repr。

## 6. JSONL 最小契约与错误处理

默认目录是 .codesage/deep-review/<run_id>/events.jsonl。append 接收 run_id、record_type、payload；store 加入 schema_version=1、从 1 开始的 sequence、UTC timestamp。先序列化完整一行，再追加并 flush。新 run 目录独占创建，不能打开旧 run 继续追加。

stdout 只在没有 --output 时包含一个 JSON 对象；进度和错误写 stderr。路径不存在、非法 ref、非法配置退出 2；运行期间分析失败或存储写失败退出 1；成功到达 anatomy 退出 0。捕获异常后尽力写 run_failed，写失败本身不得进入无限重试。CancelledError 继续传播，CLI 中断退出 130；中断记录的完整可靠性在 25.7 加强。

Preparation 阶段不创建最终 result.json；开发者指定的 --output 是准备报告。JSONL 中只保留计数、路径、commit、摘要和诊断，不保存完整 Anatomy、diff、源码或环境变量。

## 7. 技术约束与红线

- 不导入 RuntimeBridge 来完成 --help 或 anatomy。测试中应把 RuntimeBridge 构造替换为抛异常，证明完全不会访问。
- 不调用 Evidence：本包还没有 Candidate，不能用空 Finding 伪造证据阶段成功。
- 不 checkout、reset、clean，也不修改被审查仓库。固定 head 读取不受工作区修改影响。
- 不增加网络抓取、数据库表、stage resume 或历史 run 读取。
- 不把已排除文件的完整路径和内容无条件写入 report；secret 排除只需计数与原因。
- 原型成功报告和最终 DeepReviewResult 保持明确类型区别。

## 8. 测试用例设计

测试仓库通过 tmp_path + git init 创建，并配置局部 user.name/user.email。至少创建新增文件、修改文件、删除文件和一个 secret 路径；构造两个 commit，不依赖本仓库历史。

| 编号 | 场景和输入 | 必须断言 |
|---|---|---|
| A01 | 正常 base/head | report 到 anatomy；commit 完整；pipeline_complete=false；零模型调用 |
| A02 | 修改工作区但不提交 | report 与固定 head 一致；工作区字节未被更改 |
| A03 | base/head 不存在 | 退出 2；stderr 可定位错误；没有伪造成功报告 |
| A04 | --through planning | 在执行前拒绝，退出 2 |
| A05 | secret + deleted | secret 不进入下游摘要；deleted 属于 context |
| A06 | filter 调用计数 | 一次 intake 只过滤一次 |
| A07 | 已知 BlastRadiusError | 到达 anatomy，related_paths 为空并带诊断 |
| A08 | store 第二次 append 抛 OSError | run 失败；无成功事件；不反复重试写入 |
| A09 | 相同输入连续跑两次 | 两个不同 run 目录；稳定业务字段相同 |
| A10 | CLI 有/无 --output | 有文件时 stdout 为空；无文件时 stdout 可整体 JSON 解析 |
| A11 | 空 diff | 合法空准备报告；不调用任何模型 |
| A12 | 注入 memory store | 编排正确，无存储目录耦合 |
