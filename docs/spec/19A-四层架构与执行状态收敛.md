## 目标依赖

`api → control_plane contracts/queries`；`control_plane` 不依赖执行实现；`execution_plane → domains/pr_review + tool_gateway + control ports`；`tool_gateway` 不依赖 API、PR 编排或生命周期；`domains/pr_review` 不依赖 FastAPI、ARQ、SQLAlchemy、settings、Phoenix。

目标包：`control_plane`、`execution_plane`、`tool_gateway`、`domains/pr_review`、`contracts`、`infrastructure/{messaging,persistence}`、`bootstrap`。迁移完成后删除 `app/services/agent`，生产与测试不得再导入它。

## 职责与事务

- 控制平面拥有 start/cancel/resume、delivery、lease/epoch、可信预算/权限快照、阶段及终态事务。
- PR 领域拥有输入语义、提示词、三视角编排、规则、finding 规范化与完成判定。
- 执行平面拥有 Worker supervision、heartbeat/cancel、Harness/QueryLoop、模型和 Session 执行。
- ToolGateway 是 schema → policy → executor → output governance 的唯一入口；FinalizeReview 只返回领域验证结果。
- `session_start` 经 fenced result service 将 pending stage 原子改为 running，并设置 `started_at/session_id`；completed stage 不允许被迟到事件降级。
- workflow 不直接 commit；Stage/Findings/terminal 只由结果服务提交。

## 迁移策略

1. 先增加跨层 import AST 测试和入口/事务清单。

3. `app.worker.agent_worker` 仅保留兼容启动薄入口；ARQ 实现归 messaging，业务执行归 execution plane。
4. Session/Message/Turn/Checkpoint、StageResult/Run/Findings/ArtifactRef 保留；`AuditModelStreamAttempt` 的物理删除留给 19B。
