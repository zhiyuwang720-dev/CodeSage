## 1. 目标、不变量与交付边界

### S20-G01 诊断能力

一次审查必须可追溯实际模型请求、响应、工具参数/结果、逐请求 usage、时间与已知成本，能关联视角、turn、执行 attempt、取消/恢复及最终发现处理。Phoenix 负责在线分析，诊断包负责离线人类/Agent 分析。

### S20-G02 架构及业务不变量

保留接入层、控制平面、执行平面、工具网关，保留 QueryLoop、SessionStore、三视角、提示词、模型默认配置及现有审查判定。不得增加新的 Agent、改评分算法、恢复 AuditModelStreamAttempt 表或使 Phoenix 成为状态真源。

数据库 lease/epoch、Checkpoint、ToolExecutionReceipt、StageResult、终态事务依旧权威。Trace/日志可能丢失；不能用于授予权限、恢复 owner 或伪造完成。Exporter/内容记录失败不得改变业务执行；业务持久化失败不得被 telemetry 的异常处理吞掉。

### S20-G03 状态与缺失

所有展示与聚合区分 `observed`、`derived`、`estimated`、`missing`，以及明确数值 0。代码中禁止 `raw_value or fallback` 判断数值是否存在。0 是合法值，空字段不是 0。

Phoenix 金额与本地金额均为基于记录 usage/价格的估计账单，不宣称替代供应商结算单。中断请求不知道收费与否时标未知，不能推算“省下”的金额。

### S20-G04 基线记录

执行开始记录 HEAD、dirty 文件清单和补丁哈希、Python/依赖锁版本、Phoenix image digest、启动方式与已脱敏配置。本版勘察 HEAD 为 e6b5d2056d3555ce0d3cd651eb07c55a412353a0，必须重新确认。禁止打印 .env、API key 或完整配置密文。

基线测试覆盖 observability、models/adapters、runtime、tool_gateway、session、控制平面、队列/Worker、codesage_eval、前端 typecheck。保留原始输出、退出码、已有失败；测试阻塞与业务失败分开。

## 3. 标识、上下文与 Span

### S20-T01 关联字段

业务上下文保留以下独立字段，禁止泛化同名 attempt_id 覆盖：

| 字段 | 含义与生命周期 |
|---|---|
| task_id / review_run_id | task 与逻辑运行；resume 不改变 review_run_id |
| delivery_id | 一次业务投递；ARQ 对同条消息重试仍属同 delivery |
| execution_attempt_id / lease_epoch | claim 成功后确定，owner 更换时变化 |
| session_id / turn_id | 实际 Harness session/turn；不是 PR run |
| model_attempt_id | QueryLoop 内模型尝试 |
| provider_request_id | 一次真实请求，发送前生成；供应商 request ID 另存 |
| tool_call_id | 业务工具回执 ID，不能替换成 span_id |
| perspective / purpose | security/architecture/quality；review/finalizer/compaction/judge |
| eval_run_id / case_id | 非评测运行允许为空 |

Span 扩展属性使用 `codesage.*`；标准 `session.id` 使用实际 session_id。run 聚合三个 session 依赖 review_run_id，不伪造单一 session。标准 trace_id/span_id 由 OTel 生成。

提供通用运行关联上下文，替换只能覆盖 eval 的命名/绑定；不再实现自定义 Trace 协议。绑定以 context manager/finally 复原。asyncio 子任务继承正确 context，线程池显式复制；线程完成后不能污染下一任务。

### S20-T02 层级与请求真实性

```text
task.publish → worker.receive
                  └─ ownership.claim
                  └─ execution.attempt（仅 claim 成功）
                      └─ review.quick
                          └─ review.<perspective>
                              └─ harness.turn
                                  └─ model.attempt
                                      ├─ model.admission
                                      ├─ provider.request
                                      └─ retry.backoff
                                  └─ tool.invoke
                      └─ result.commit
```

receive/claim/attempt 的精确父子可因现有 supervisor 分层实现调整，但必须保证 receive 不计有效 owner；claim 失败不能产生成功 execution attempt，执行耗时起于有效领取。

图中 provider.request 是归一概念，允许保留 LiteLLM 官方 integration 的 Span 名称。模型计费 Span 由 SDK integration 生成，业务 Span 不再包装同一请求形成重复 LLM。映射实际 request ID 到 SDK span/callback ID，不能凭时间/模型猜配对。使用统一 TracerProvider、exporter、resource 和 W3C context。

最终输入由锁定SDK公开hook采集；仅SDK输入标 payload_fidelity=sdk_input，本地HTTP确认脱敏语义等价才可wire_equivalent。实际启用路径必须通过等价验收。不得复制厂商协议适配来获取正文。

重试归属按P0 P05，唯一请求计数按P0 P08。逻辑请求回调不能代替实际attempt；官方OTel粒度不足先按P0能力门解决。缺口未解决必须暴露，不允许用额外外层LLM span假装真实请求。

父 Span 不重复设置 llm.token_count.*。辅助 LLM 必须计一次且有 purpose。逻辑模型名如 review:security 只在逻辑上下文，不进入 llm.model_name。

### S20-T03 消息与恢复

队列仅传白名单 W3C traceparent/tracestate，新增可选 queued_at UTC（入队调用前的发布时点，只有 enqueue 返回新 job 才确认；标明精度包含发布 RTT）。旧消息缺字段标 missing，不伪造 0。入队返回 None 按重复 job 分类，不能计 submitted。

恢复创建新 attempt Span，通过稳定 run ID 与已知 Span Link 关联；不重开旧 Span。阶段复用事件含 source session/stage/attempt（可得时）和 findings 数，无新 provider Span。恢复继续工作与确认重放分别计数；无法证明重复的记 recovery_new_work/unknown。

### S20-T04 状态

成功显式 OK；provider/工具返回错误即使未抛异常也 ERROR。user cancel 标 cancelled，OTel UNSET + cancellation event，不归为供应商故障；实际网络错误仍 ERROR。already_owned 和 ARQ Retry 标 deferred，不标执行失败。result.commit 仅实际事务成功后记录 terminal_committed；commit 出错 ERROR 并保留原业务异常。

Exception、status description、Span events、link/resource 字符串属性必须脱敏。不得只保护 input/output。

## 4. 模型 usage 与计费契约

### S20-U01 类型

扩展现有 LLMUsage/LLMResponse/RuntimeModelResponse 与流式 done/error payload，保持现有调用可兼容。导出归一记录字段：

```text
schema_version=1
configured_model, request_model, response_model?, provider, endpoint_id, protocol
input_tokens?, output_tokens?, total_tokens?, cache_read_tokens?, cache_write_tokens?, reasoning_tokens?
field_sources: {field: provider|derived|missing}
estimated_usage?: {input_tokens?, output_tokens?, method, version}
raw_usage_ref?, normalization_version, anomalies[]
```

问号表示 nullable；不存在值在 OTel 中省略属性，在 JSON 中为 null。整数不得负数/非整数，异常值保留原始脱敏数据和 anomaly，不截断成合法零。estimated_usage 不写标准计费字段。

### S20-U02 归一化

- DeepSeek hit/miss 字段与 prompt 总量一致时：cache_read=hit；uncached=miss。hit+miss 与 prompt 冲突记 anomaly，精确费用不通过。
- OpenAI-compatible：prompt 总量包含 cached；uncached=prompt-cache_read。cached>prompt 记 anomaly。
- Anthropic：区分provider_raw和sdk_normalized；原生数据按已验证包含关系归一，SDK已归一的数据不能再次把cache加到input。禁止只凭provider名称决定算法。
- total 缺失但 input/output 均明确时可 derived=sum；只有一个明确时 total=null。
- reasoning 是 output 子集时不再相加。cache_write 是否另计由价格/协议适配确定。
- 对第三方 SDK 合成的全零：只有原始响应确认包含零才能标 provider；无法区分标 missing/anomaly，不能武断称明确零。
- 错误/partial 返回 usage 同样保留；错误只有估算时保留 estimated_usage。
- 供应商显式零不被估算覆盖。Harness 预算估算可保留，但来源不能丢失；预算内部保守估算与报告实测消费分开。

数据流逐段不可丢字段：SDK response/callback → 薄 service → bridge → runtime → StageResult 摘要/Span/诊断导出。API 若需保持零值显示兼容，只在兼容投影处理，不污染归一事实。

### S20-U03 OpenInference

标准属性来自归一结果：llm.model_name=request_model（真实供应商模型名；内部路由前缀另存）、llm.provider、llm.token_count.prompt/completion/total、prompt_details.cache_read/cache_write、completion_details.reasoning。response model 另存，并在价格解析时显式选择 provider 计费模型。

优先使用SDK标准字段，仅在集中integration补齐缺失。OTel GenAI 映射放一处，锁定语义版本；测试确保 Phoenix 当前版本识别字段。不能用前端手工改一条 Trace 证明自动接入。

### S20-P01 价格与计算

本地价格目录 JSONL 每条包含 schema_version、price_id、provider、endpoint_id（不含凭据）、model/aliases、currency、effective_from/to（UTC 半开区间）、per_million 单价、source、version。

同 endpoint/provider/model/time 必须唯一匹配；0 条为 price_unknown，多条为 pricing_conflict。aliases 必须显式配置，禁止模糊包含匹配。请求开始时间决定价格版本。

以下是验收数学oracle，不是生产代码实现要求；生产使用LiteLLM冻结价格计算能力。普通缓存分价例（测试币种 USD）：cost=(uncached_input*input_price + cache_read*read_price + cache_write*write_price + output*output_price)/1e6。类别必须不重叠；按 provider 归一，未收费的类别配置零而非重复计算。SDK计算结果保存来源/版本；项目使用Decimal进行金额聚合，JSON金额为十进制字符串，展示层才舍入。SDK浮点结果按验收容差比较，不声称计算内部使用Decimal。

例：input=1000、cache_read=400、output=200，测试价 miss=1、read=0.1、output=2 USD/百万，cost=0.00104 USD。缺 cache_read 且存在缓存分价时不能给精确总价；可展示不依赖未知字段的已知小计，不能默认全未命中。

提供 `python -m app.diagnostics pricing doctor --catalog <file>` 与 `pricing sync --catalog <file>`；doctor 只读、sync 显式写 Phoenix 价格配置，输出匹配/新增/更新结果。固定 Phoenix 版本不支持的定价必须报告 unsupported；真实成本验收不能通过。

Local/Phoenix 使用同一版本目录，并把冻结输入交给LiteLLM的受支持价格配置/计算能力；禁止另外实现厂商计费引擎。callback response_cost须通过模型/端点/价格/usage完整性校验后才能采用；缺失不写0。SDK计算与Phoenix估算不一致时输出差异，不静默选择较低值。不自动抓取在线报价，不改现有模型/endpoint。真实 DeepSeek 来源或价格未确认时仅价格验收 blocked。

## 5. 内容采集、产物与授权

### S20-C01 开关与边界

OTEL_CAPTURE_CONTENT=false 默认；true 由独立 local-diagnostics profile 显式传入，不覆写用户 .env。false 不存/导出正文，仍生成脱敏规范内容的 hash、size 与 disabled 状态。true 捕获最终请求、完整可见响应、tool raw/validated arguments、授权判定、结果、compact 摘要和 finding 决策。

工具 rejected-before-parse 的 validated arguments=null，不制造解析成功。partial 响应记录 partial=true，finish_reason 不存在则 null。隐藏模型推理不可获得，不生成假 reasoning。

### S20-C02 存储

复用 ArtifactRef 路径/哈希验证，独立诊断存储适配异步写入，不沿业务结果事务提交。推荐根 `.codesage/observability/content/<run_id>/`，Compose 映射同一受控 root；文件路径不含原始 repo 名和用户输入。

记录 artifact_id、kind、关联 IDs、media_type、relative_path、sha256、stored_bytes、original_redacted_bytes、capture_status、reason、redaction_version。hash 对脱敏后保存字节计算。preview hash 与完整 hash 不混用。

状态：captured/truncated/missing/reconstructed/disabled；文件排队待写为 pending，仅写成功可 captured。超限保留有界前缀并标 truncated；缺失不创建虚假 ArtifactRef。

限制固定为 Phoenix 内容预览合计每 Span 32 KiB（跨全部消息属性，不是每消息32 KiB）、单产物16 MiB、单run256 MiB。须同时处理 OTel attribute 数量上限；不能宣称完整但 SDK 已丢后续消息。32 KiB 以内可完整显示；更大内容通过下载/诊断包获取。

run配额跨进程/恢复使用受控根下原子 reservation/文件锁，短持锁，只负责诊断存储，不复用业务 lease。锁失败则记内容缺失，不阻塞业务。超限、落盘失败、drop 使 content completeness 降级。

### S20-C03 脱敏与接口

脱敏在入日志/队列/文件/exporter 前进行；JSON 字符串中的 API key/password 字段需解析/递归或等价保护，不能只靠 sk- 正则。覆盖 Authorization、URL userinfo、secret query、异常、工具输出中的已知凭据；不承诺检测所有语义秘密，报告 redaction policy/version。

新增 `GET /api/v1/agent-tasks/{task_id}/diagnostics/artifacts/{artifact_id}`：复用当前任务读取授权，校验 task→run→artifact 归属、路径、symlink 与hash。不接受绝对路径参数。404 对不存在/不归属统一返回；完整性失败409 `artifact_integrity_error`。不返回服务器路径。下载默认 attachment，防止执行HTML。

Phoenix 预览使用 input.value/output.value、message role/content、tool.name/tool.parameters 与 MIME 属性；大内容添加 artifact ID及受认证下载链接。严禁公开无认证文件服务器。

### S20-C04 发现与压缩 provenance

每次 filter/merge 记录 input finding IDs、output IDs、reason code（severity/location/duplicate/budget 等实际规则）、规则版本。不改判定逻辑。compact 记录触发类型、输入输出字符/消息数、实际模型 request IDs；token 仅来自 U01，不用 len(text)。finalizer/compact Span purpose 不缺失。

## 6. Metrics 与时间规范

### S20-M01 仪器

初始化一次仪器。Counter 单位 `{operation}` 或 `{token}`，Histogram 时间单位 s；JSON 诊断可投影为 ms，但字段后缀明确。仪器目录集中定义：

| 名称 | 类型 | 触发 |
|---|---|---|
| codesage.task.submissions | Counter | 新任务首次成功提交；resume 不计 |
| codesage.task.terminal_transitions | Counter | 实际提交终态后；表示转换不是唯一任务 |
| codesage.execution.attempts | Counter | 有效 claim 成功 |
| codesage.execution.lease_lost / recoveries | Counter | 所有权丢失/恢复有效领取 |
| codesage.harness.turns | Counter | started/completed 状态分组 |
| codesage.model.requests | Counter | 真实请求终止，status分组 |
| codesage.model.retries | Counter | 实际安排重试，layer分组 |
| codesage.model.tokens | Counter | provider/derived 已知量一次累计，token_type分组 |
| codesage.tool.calls | Counter | 每次网关调用终止，status分组 |
| codesage.compactions | Counter | 触发/完成 |
| codesage.<queue/claim/execution/perspective/admission/provider/tool>.duration | Histogram | 对应有效测量结束 |
| codesage.telemetry.export_failures / dropped / truncated / usage_missing | Counter | 明确失败/缺失 |

tool.calls status 聚合出denied/failed，避免多组计数口径漂移；retry layer包括query_loop/sdk/arq/recovery；service/adapter重试在P0删除，仅历史记录允许出现。允许有界标签 provider/model/purpose/perspective/status/error_kind/tool/layer/exporter；禁止 IDs/路径/消息正文为标签。

### S20-M02 聚合

时间区间沿 Plan 20：command response、queue、delivery-to-claim、claim、effective execution、perspective、admission、provider、tool、recovery。OTLP Span 保留 epoch纳秒，进程内诊断时长来自 perf_counter；跨主机只能依赖校准 UTC，出现负值标 clock_anomaly，不钳成零。

速率默认60秒窗口，可显式指定：token consumed rate=窗口内新增确认token/窗口秒数；这是消费吞吐，不是provider瞬时生成速度。累计Counter按resource/service.instance.id/start_time拆系列并差分，首快照依赖start_time；窗口边界无法精确分配时标approximate。进程重启新系列不得与旧累计相减。

output generation rate=已知output token/(last_content_delta-first_content_delta)，只在确有多个内容增量、时间>0、usage已知时展示；非流式/done-only/单delta为N/A，名称注明近似。

任务完成率从cohort的唯一task当前终态计算：completed/submitted，截至cutoff运行中、failed、cancelled分别显示；不能对terminal_transitions Counter求比得到cohort完成率。resume后最新有效状态覆盖原状态，但保留历史。

p50/p95/max均带样本数与方法（nearest-rank）；0样本null，<20样本p95标small_sample，不做提升结论。并行资源时长相加与墙钟分开。

## 7. Logging、批量导出与启动

### S20-L01 日志格式与位置

JSON日志schema_version=1，每行：UTC timestamp、severity、logger、event_name、message、service、process_instance、trace_id/span_id（无上下文null）、业务关联字段、error_kind、脱敏exception、artifact_refs、process_sequence。

默认根 `.codesage/observability/logs/`，每进程 `<service>-<instance_uuid>.jsonl`，20MiB轮转、5个备份；console也JSON。instance UUID每次启动新建，PID重用不能合并。父process目录manifest记录实例与文件映射。

事件至少覆盖task accepted/published/cancelled/resumed、owner acquired/lost、stage started/reused/completed、retry scheduled/exhausted、tool denied/failed、compact、finding decision、terminal committed、telemetry error。不记录逐token正文。

日志关联在LogRecord生成/统一formatter处完成，不能只给现有handler挂Filter。后建handler、async任务、显式线程池传播覆盖；无context的后台日志不猜测session。

### S20-E01 导出

OTLP与本地export分别使用BatchSpanProcessor，有界队列默认2048 spans、batch512、schedule1s；标准SDK无法暴露drop计数时增加仅计数的processor适配，不再实现Trace协议。内容队列总待写字节上限64MiB、日志队列10000条；溢出诊断失效但不阻塞审查。

文件独立到process instance。OTLP标准JSONL不混进业务日志。正常退出flush共享10秒总预算（非每队列10秒叠加）；导出异常/超时记录到直接stderr fallback，避免递归使用故障exporter。force_flush返回综合结果，不能只flush Trace。

两种Worker入口与API使用同一bootstrap；禁重复set全局provider。SimpleSpanProcessor仅测试可用，生产文件写入不得在请求event loop同步执行。硬杀未结束span为unknown，无法保证不丢失。

## 8. 诊断CLI、完整性与报告

### S20-X01 CLI

正式命令前缀 `python -m app.diagnostics`：

```text
export --run-id <uuid> --output <new-dir> [--public]
summarize --input <bundle-dir>
pricing doctor --catalog <jsonl>
pricing sync --catalog <jsonl>
smoke --case-id <fixture-id> --allow-paid --max-cost <decimal> --currency <code>
```

export需要本地持久化读取权限，支持Phoenix+本地文件合并；summarize纯离线无DB/network/模型。output非空默认拒绝，重复执行用新目录，避免覆盖证据。退出码0完整、2产出但不完整、1执行错误；真实smoke无allow-paid必须拒绝。价格未知且无法执行金额预算时不得发付费请求，记录阻塞；不新增凭据CLI参数。

成本预算是已知消费约束，不能保证已在途请求零超额；smoke限制1个固定case并保留业务token/turn/deadline上限，报告在途风险。该命令的实现不表示已授权本次文档任务调用模型。

### S20-X02 包格式

bundle包含manifest.json、timeline.jsonl、logs.jsonl、model-calls.jsonl、tool-calls.jsonl、findings-decisions.jsonl、metrics-summary.json、completeness.json、contents/、report.html。

manifest含schema/spec版本、输入run IDs、代码/配置指纹、源文件哈希、价格版本、capture/redaction策略、cutoff、sources和每文件sha256。每条投影必须有source_type/source_id，不能编造原始事件。模型行以provider_request_id为键；工具行以tool_call_id为键；Span去重按trace_id/span_id。

timeline排序timestamp、process_instance、process_sequence，跨进程仅视为时间排序非绝对因果，因果依赖parent/link/业务ID。summary必须确定性；重复summarize同包语义结果相同，生成时间不参与指标指纹。

### S20-X03 完整性

每维度状态 `complete|partial|unknown|not_applicable`，并包含expected/observed/missing_ids/reasons。expected不能仅由已经看到的Span生成，需对照业务StageResult、turn、工具回执、请求开始日志和配置。

- execution：业务终态与阶段门禁。
- trace：相关Span收齐、可对齐回执；分页不能limit10截断。
- usage：每个已知请求的必要计费字段完整；可能存在未知请求则不能complete。
- content：capture关闭为not_applicable，不能满足诊断profile的完整正文验收；截断/丢失partial。
- logs：实例片段/sequence/轮转范围/结束记录可对齐；缺历史片段partial。
- pricing：对应已知请求唯一有效价。
- result_provenance：终态发现与filter/merge决策可核对。

Phoenix查询分页至游标耗尽，按case/run/trace过滤，默认60秒总等待、0.5至2秒有界退避；发现一条不提前宣称完成。到期仍导出可得内容并标partial。Phoenix client阻塞调用不得阻塞异步Worker（查询仅在控制/导出路径）。

旧transcript重建为reconstructed，包含原记录来源；不能通过补写旧provider Span改成wire_equivalent。

### S20-X04 报告

HTML从包/评测JSONL独立生成，无CDN/DB/Phoenix依赖；保留原质量算法，增加时延/token/费用/轮次/工具/恢复和完整性。provider父子不能重复求和；request→perspective→run→experiment只有一个账本聚合器，复用冻结价。

public导出不拷贝完整contents，移除内部endpoint/路径/凭据/原prompt/source/私有异常；保留公开findings/golden需沿现有公开数据策略。防`</script>`、HTML注入、恶意产物路径。Phoenix深链是可选导航，不是读取报告的前置条件。
