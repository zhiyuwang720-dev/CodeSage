# Spec 18：执行服务拆分与 PR 语义收敛

状态：已实施并完成真实 Worker 验收。对应已批准的 `docs/plan/18-执行服务拆分与PR语义收敛.md`。

## 1. 基线与边界

- 基线：`origin/master@6a0324e760ea32f7f184d7740e66534f916d01d8`，实施分支 `codex/18-pr-review-service-split`。
- 初始 tracked diff 为空；未跟踪源码集中在 `code-review-benchmark/`，其余为本地配置或 pytest 产物。本工作项不修改、不清理这些用户文件。
- 不增加第三方依赖，不开发深度审计、路由、Skill、权限、发布或计费功能。
- 第二轮补充说明优先于前文歧义：生产只支持 worker 调度；PR 新写路径以 `category` 为唯一领域类别。数据库旧列是否物理保留遵循“本轮无 destructive migration”，仅作为集中 legacy 读取投影，不参与新写、去重或完成门禁。

## 2. 模块与依赖

- `inputs.py`：唯一输入准备入口；解析纯 diff 或本地 Git 固定范围，写入并验证 input artifact，构建/校验稳定身份。执行只消费该固定输入。
- `quick_review.py`：薄用例协调者；恢复预填、调用既有 pipeline、形成规范结果；不调用 `commit()`。
- `execution_events.py`：显示事件与持久化阶段事件分离；显示失败不影响 checkpoint，checkpoint 失败向上传播。
- `results.py`：唯一 PR 结果写入服务；阶段可独立事务，最终 Findings、report StageResult、task terminal 同一事务并受 owner fencing。
- `lifecycle.py`：start/cancel/resume 锁内校验与状态转换；提交成功后才发本地通知或入队。
- `execution.py`：attempt/lease/heartbeat/子任务监督和生产依赖组装；默认路径直接调用服务内 quick review，不导入 API。
- API 只保留鉴权、HTTP/SSE 适配和薄兼容包装；worker 与 services 的 AST 不允许 `app.api` import。

## 3. 输入和恢复不变量

1. 首次执行必须先持久化稳定身份及可信 input artifact，再允许 claim/运行。
2. Git 输入只接受本地仓库中可验证的 base/head commit；diff 哈希来自固定范围的真实 bytes。
3. URL 与显式 diff 同时存在时，显式 diff 优先；pipeline 不再次获取移动 PR。
4. resume 加载既有 run_id，使用同一实现重新准备声明输入并比较身份，随后 `read_verified()`；不得生成新的持久化身份。
5. 初始化、身份和输入引用一次事务写入；中途退出可幂等重试。

## 4. 生命周期和结果不变量

1. `quick_review.py` 不提交数据库。lease/heartbeat 仅由 ownership 提交，控制命令仅由 lifecycle 提交，阶段和最终业务结果仅由 results 提交，SessionStore 保持自身事务。
2. Findings 在完成门禁之后归一化；FAILED/CANCELLED 不留下未引用的最终 Findings。
3. 最终 Findings、不可变 final artifact 引用、report StageResult 和 COMPLETED 终态在一个 owner 守卫事务内提交。
4. report/checkpoint 失败必须回滚结果事务并进入 FAILED；不能宽 catch 后继续 completed。
5. SSE/展示事件失败可忽略；stage/checkpoint 写失败不可忽略。
6. 新 PR finding 的指纹使用 category；`security`、`perf`、`test_gap` 等原样保存，CVE/PoC 契约不进入新写路径。

## 5. Worker 与故障恢复

- `AGENT_TASK_EXECUTION_MODE` 默认 `worker`；旧 `inline/local` 配置明确拒绝。
- 单消息崩溃恢复复用生产 worker handler/retry；两个 worker 常驻，只 enqueue 一次，不手动 resume、不写业务状态。job timeout/max tries 必须使 90 秒接管可达。
- runner、heartbeat 由父执行监督并在退出时 cancel + await；所有权丢失只终止本地 attempt。

## 6. 数据迁移与兼容

- 为 `agent_findings` 增加可空 `category`；新 PR 写入 category，并把版本化 `review_payload` 放入现有 metadata JSON。
- 旧 `vulnerability_type` 物理列本轮保留，仅 legacy 读取适配使用；新 PR 指纹、API 规范字段和报告不依赖它。
- 干净库与历史 fixture 验证 upgrade/downgrade；downgrade 仅移除新增 category，不触碰旧列。

## 7. 验收

- 先补失败测试：结果事务故障、单消息崩溃、非空类别、输入固定、AST 依赖、公开 cancel/resume。
- 正常、公开取消恢复、单消息崩溃恢复各连续三次；覆盖重复投递、旧 owner、心跳、假完成、输入/StageResult/产物损坏。
- 独立子进程不加载 `app.api`，通过默认服务入口完成非空审查。
- 一键报告基于 JUnit XML 输出精确 nodeid、skip 原因、未实现/未运行项，并导出 worker、attempt、模型调用、阶段、DB 与 artifact 证据。
- 执行 worker/queue/executor/resume、stage/checkpoint、runtime/session、API、迁移及前端类型检查相关回归；任何既有失败按精确 nodeid 和特征记录。

## 8. 实施结果与兼容清单

- 活跃 PR 路径：`ReviewFinding.category` → `ReviewResultService` → `AgentFinding.category` → API/报告 `category/finding_type`，不经过 CVE/PoC 完成契约。
- 历史兼容：物理列 `vulnerability_type`、旧响应字段和历史安全证据字段继续只读保留；无法恢复类别的旧记录显示 `uncategorized`，不猜测回填。
- 已删除：endpoint 内快速审查执行体、恢复预填、阶段事务、最终 findings 写入和 CVE 型 `_save_findings` 写路径。
- 退役条件：当历史漏洞记录完成独立归档/API 版本下线后，另起 destructive migration 删除 `vulnerability_type`；不在本轮执行。
- 最终证据见 `backend/tests/worker_acceptance/PLAN18_RESULTS.md`。真实矩阵 31 passed、1 skipped；相关回归 322 passed、2 个精确登记的既有/环境失败；前端 `tsc --noEmit` 通过。
